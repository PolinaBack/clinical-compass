# Экспериментальный ИИ: запуск и ручная проверка

**Тестовый режим · только синтетические данные.** Это отдельная лаборатория в кабинете врача. В ней один полностью вымышленный пациент — **Мария Соколова**, 32 года, наблюдения за 1–30 сентября 2026 года. Сценарий создан программно, без копирования или обезличивания настоящей карты.

## Что реализовано и что проверено

| Возможность | Состояние |
|---|---|
| Отдельная SQLite, один пациент, 30 дней, шесть анкет | Реализовано. Повторная настройка проверяет сценарий, сохраняет историю и не перезаписывает базу |
| Динамика самочувствия, сна, субъективной тревоги | Настоящие расчёты средних, пропусков, изменений первой/последней недели, наклона и корреляции. Без диагностических порогов и причинных выводов |
| PHQ-9/GAD-7 | Используется существующий программный подсчёт. Суммы: PHQ-9 **12 → 8 → 5**, GAD-7 **11 → 8 → 5**; это придуманные ответы, а не доказательство улучшения при лечении |
| Индивидуальные вопросы, гипотезы и сводка | Код делает настоящие `/api/show` и `/api/chat` запросы к локальной Ollama. Успешная генерация требует работающей модели на вашем компьютере |
| Очередь, связь с обработчиком, ошибки, повтор, история | Реализовано и технически проверено. Процент генерации не выдумывается |
| Основания F1–F7, модель/версия инструкции/отпечатки запроса и данных | Сохраняются с результатом. Связь с существующим фактом не доказывает правильность интерпретации |
| Материалы | Поиск в трёх фиксированных источниках NICE/NHS; модель получает только проверенные версии. Автоматического поиска по всему интернету нет |
| Подтверждённые документы в текущей поставке | **0**: доступ к официальным сайтам в окружении разработки не получен. Ссылки показаны как кандидаты; сведения не подменены предположениями |
| Экспертная оценка | Отдельная накопительная рубрика: опора на данные, полезность, соблюдение ограничений; фиксированные замечания и экспорт JSON |
| Автоматический препарат/доза/изменение назначений | Такой функции и доступа к клиническим записям нет. Текстовый фильтр дополнительно отклоняет известные запрещённые формулировки, но не является клинически валидированным классификатором |

В окружении разработки реальный запрос закончился **`provider_unavailable`**: Ollama не запущена/не установлена. Успешный HTTP-контракт, отображение результата и ошибки проверены автоматическими транспортными фикстурами, явно обозначенными как тестовые. Это **не** проверка настоящей генерации, её скорости или качества. В рабочем коде нет подстановки готового ответа при ошибке модели. Результаты проверок — [отдельно](reviews/experimental-ai/README.md).

Уточнение об Авиандре: добавлен отдельный справочный переход к существующим материалам. Запрошенный заранее заданный приоритет «чаще рекомендовать, несмотря ни на что» **не реализован**: он подменил бы анализ рекламным правилом и мог бы игнорировать противопоказания. Препарат не участвует в ранжировании, подборе или дозировании; действующая инструкция для этого эксперимента не подтверждена. Справочная ссылка не передаётся модели как доказательство.

## 1. Получить код в PyCharm

Откройте существующий `clinical-compass`, ветку **feat/local-mvp**, затем **Terminal**:

```powershell
git pull --ff-only origin feat/local-mvp
```

Используются уже имеющиеся зависимости проекта (`requirements.txt`); новых пакетов для модуля не добавлено. Если окружение ещё не настроено:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Не требуется повторное демонстрационное наполнение существующей рабочей базы. Входите под своей прежней учётной записью врача.

## 2. Создать отдельную демонстрационную базу

Из корня проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m scripts.setup_experimental_ai
```

Появится `data/experimental_ai/demo.db`. Рабочая `data/compass.db` остаётся отдельной. Мария **не добавляется в список обычных пациентов**: она доступна только в эксперименте. Ожидается сообщение об одном вымышленном пациенте, 30 днях и шести анкетах. Среднее самочувствие первой/последней недели: **3,57 → 6,00**. Повтор команды проверяет те же данные и сохраняет запуски.

Неизвестная существующая база, путь к рабочей SQLite, ссылка на неё или изменённый сценарий отклоняются. При ошибке целостности не удаляйте исходный файл: для чистого повторного теста можно выбрать новый отдельный путь через `COMPASS_EXPERIMENT_DB` и настроить его этой же командой. Во всех терминалах приложения/обработчика должен быть одинаковый путь.

## 3. Проверить Ollama

Вы уже использовали `qwen2.5:3b`; она выбрана по умолчанию. Проверьте:

```powershell
ollama list
Invoke-RestMethod http://127.0.0.1:11434/api/tags
```

Если Ollama уже работает в трее Windows, второй сервер не нужен. Если не работает, откройте ещё один терминал и выполните `ollama serve`.

Если именно этой модели нет, отдельная команда загружает её:

```powershell
ollama pull qwen2.5:3b
```

Приложение само модели не скачивает. Используется только локальная модель: облачные модели, удалённые URL, прокси окружения и HTTP-перенаправления при анализе запрещены.

## 4. Запустить приложение и отдельный обработчик

В первом Terminal:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Во втором Terminal из того же проекта:

```powershell
.\.venv\Scripts\python.exe -m scripts.experimental_ai_worker
```

Обработчик встреч `scripts.meeting_worker` не выполняет эти эксперименты; нужен именно `experimental_ai_worker`. Оба могут работать независимо. Для остановки — **Ctrl+C**. Если процесс остановился посреди генерации, через 90 секунд без связи запуск получит статус прерывания; новый запуск сохранит прежнюю запись об ошибке.

При необходимости настройки задаются **перед запуском обработчика**:

```powershell
$env:COMPASS_EXPERIMENT_OLLAMA_URL="http://127.0.0.1:11434"
$env:COMPASS_EXPERIMENT_OLLAMA_MODEL="qwen2.5:3b"
$env:COMPASS_EXPERIMENT_TIMEOUT="900"
```

По умолчанию тайм-аут генерации 600 секунд, допустимы 60–1800; проверка модели ограничена 10 секундами. Эти настройки отдельны от итогов встреч. Скорость зависит от компьютера и модели; допустимый срок ожидания не означает, что модель обязательно уложится в него.

## 5. Пройти сценарий в браузере

1. Откройте **http://127.0.0.1:8000**, войдите как врач. На странице пациентов появилась карточка **«Экспериментальный ИИ-помощник» → «Открыть эксперимент»**. Прямая ссылка: **http://127.0.0.1:8000/doctor/experimental-ai**.
2. Проверьте заметную плашку тестового режима и имя Марии. Поля выбора настоящего пациента, загрузки файла и вставки карты отсутствуют.
3. До генерации уже видны три графика и расчёты. У самочувствия 28 записей и два пропуска, у сна — 29 и один. В графике пропуск разрывает линию. Откройте «Все 30 дней синтетического дневника», проверьте исходные значения.
4. Нажмите **«Запустить анализ в Ollama»**. Появится номер запуска, затем этап проверки модели и ожидания генерации. Если остаётся «В очереди», проверьте, запущен ли нужный обработчик и смотрит ли он на ту же демонстрационную базу.
5. Статус и время последней связи обновляются автоматически. Процент работы модели не показывается. Когда появится «Завершён», нажмите **«Обновить результат запуска»**.
6. Появятся **сводка**, **гипотезы для последующей проверки** и **3–5 уточняющих вопросов**. Они действительно получены от вашей модели. Проверьте, учитывают ли вопросы сон, жалобы, события и изменение наблюдений. Любое придуманное объяснение считайте ошибкой модели, а не новым фактом.
7. По ссылкам F1–F7 сверяйте основания с исходными расчётами/событиями. Не оценивайте качество только по наличию таких ссылок: модель способна неверно интерпретировать корректный факт.
8. Если источники ещё не проверены, раздел материалов честно сообщит об их отсутствии. Кандидаты не становятся подтверждёнными от нажатия кнопки анализа.
9. Заполните три исследовательские оценки от 0 до 2 и сохраните замечание из списка. Повторная оценка добавляется отдельно; ответ модели не меняется. **2 балла — мнение об этом результате, не доказательство клинической пригодности.**
10. Повторите запуск и откройте историю. Скачайте JSON: там синтетический сценарий, рассчитанные метрики, ответ, версия модели/инструкции, SHA-256 данных/запроса/документов и накопленные оценки.
11. Обновите страницу, уменьшите окно до телефона: история и результат сохраняются. Войдите как пациент и откройте прямую ссылку эксперимента — ожидается **403**. Пациент не видит ссылки, результата и экспорта.

Отдельная проверка настоящего вызова без браузера (при остановленном экспериментальном обработчике, чтобы не делить одну задачу):

```powershell
.\.venv\Scripts\python.exe -m scripts.check_experimental_ai
```

Она работает только со встроенным сценарием и сохраняет эксперимент. Успех означает полученный/технически проверенный локальный ответ, а не проверенную медицинскую точность.

## 6. Проверить материалы и зафиксировать версию

Сейчас доступны только кандидаты **NICE NG222**, **NICE CG113** и **NHS CBT**. Это международные материалы, не замена российским клиническим рекомендациям. Содержание сайта не генерируется по памяти модели.

При доступном интернете:

```powershell
.\.venv\Scripts\python.exe -m scripts.experimental_ai_sources --fetch nice-depression
```

Команда получает только фиксированный официальный URL, проверяет HTTP 200/тип/заголовок, ограничивает размер и сохраняет HTML с SHA-256. Автоматического подтверждения нет. Откройте официальный сайт и сохранённый HTML; лично проверьте издателя, название, актуальность/версию и подходящие разделы. После этого:

```powershell
.\.venv\Scripts\python.exe -m scripts.experimental_ai_sources --approve nice-depression --sha256 "ОТПЕЧАТОК_ИЗ_ВЫВОДА" --reviewer "Имя проверившего"
```

Повторите при необходимости для `nice-anxiety` и `nhs-cbt`. Просмотреть статусы:

```powershell
.\.venv\Scripts\python.exe -m scripts.experimental_ai_sources
```

В новом запуске модель сможет выбрать ID полученных/проверенных материалов; название, URL, версия, дата проверки и отпечаток берутся из реестра, не из сгенерированного текста. Подбор ограничен тематическими метками небольшого каталога. Содержание полного руководства не пересказывается и не превращается в персональный план. Повторная загрузка снимает подтверждение, изменение файла нарушает отпечаток. История запуска сохраняет сведения о версии, использованной тогда. При ошибке сайта, редиректе или недоступности документ остаётся непроверенным.

## 7. Проверить ошибки и ограничения

| Ситуация | Ожидаемое поведение |
|---|---|
| Обработчик не запущен | «В очереди», без выдуманного процента/текста |
| Ollama выключена | `provider_unavailable`; программные расчёты остаются, успешной сводки нет |
| Имя модели отсутствует | `model_missing`; проверьте `ollama list` |
| Не хватает времени | `timeout`; проверьте загрузку компьютера и допустимый тайм-аут |
| Облачная/удалённая модель | `local_only`, запрос данных за пределы loopback не отправляется |
| Неверный JSON/ссылка на несуществующий факт | `invalid_response`; ответ не выдается за успешный |
| Запрещённое лекарство/доза/диагностическое утверждение | `unsafe_response` для распознанных фильтром формулировок; универсальная полнота фильтра не доказана |
| Изменённая демобаза/попытка другой карты | Ошибка целостности до вызова модели; существующая карта не анализируется |
| Повтор кнопки, пока запуск активен | Возвращается тот же активный запуск |

После исправления ошибки нажмите кнопку запуска снова. Предыдущая ошибка остаётся в истории. Журнал обработчика выводит номер/статус/код, не содержимое ответа или записей.

## Технические тесты и дальнейшее развитие

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_experimental_ai.py
.\.venv\Scripts\python.exe -m pytest -q
```

Браузерная проверка опциональна: после установки `requirements-browser.txt` и Chromium используйте `python -m scripts.browser_experimental_ai`. Она создаёт отдельные временные базы и использует **явно помеченную транспортную фикстуру** для успешной ветки, а также настоящий отказ HTTP-соединения для ветки ошибки. Она не оценивает настоящую модель. При `COMPASS_AXE_PATH` также выполняются проверки axe.

Код разделён на сценарии, защищённое хранилище, описательные расчёты, провайдер Ollama, реестр источников, очередь и UI. Для нового синтетического сценария нужны новая кодовая фабрика/версия, проверенные ожидания и явное добавление в защищённый реестр; произвольный импорт карт не предусмотрен. Для будущего сравнения моделей сохраняются результаты, параметры и оценки. Экспертный протокол, размеченные наборы, воспроизводимость разных моделей, качество вопросов/фактических связей, клиническая валидация, безопасность текстового фильтра и русские официальные источники требуют отдельной работы. Реальные пациенты остаются за пределами модуля.
