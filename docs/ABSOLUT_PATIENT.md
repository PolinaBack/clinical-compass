# Синтетический пациент «Абсолют»

26.10.2026 · U-ABSOLUT-25. Отдельная подробная карта для «Анализа ИИ», по умолчанию у специалиста 1. Прежние пациенты A/B/C/D/E, пароли, привязки и заполнения сохраняются. Сброс и миграции не требуются.

## Добавить в свою базу в PyCharm

В терминале корня проекта:

```powershell
git switch feat/local-mvp
git pull --ff-only origin feat/local-mvp
.\.venv\Scripts\python.exe -m scripts.setup_absolut_patient --db .\data\compass.db
```

Можно выбрать существующего специалиста параметром `--doctor-id 2`; по умолчанию — 1. Команда работает только с существующей базой; в новом проекте сначала запустите обычное приложение. Путь должен совпадать с базой приложения и worker, учитывайте `COMPASS_DB`. База на вашем компьютере через Git не переносится.

Перед добавлением создаются проверенная копия `data/backups/before-absolut-*.db` и соответствующий ключ при необходимости. Операция выполняется одной транзакцией. При ошибке прежние строки сохраняются. Занятый логин и одноимённая посторонняя карта не переиспользуются. Повтор не создаёт дубликат и не перезаписывает ручные изменения, даты или пароль. При старте сайта карта сама не создаётся. **`--reset` не нужен.**

Откройте **Пациенты → Абсолют → Анализ ИИ → Авиандр — клиническая применимость**. Номер карты и адрес печатает команда. Пациентский логин — `patient-absolut`; только его новый случайный пароль сохраняется рядом с БД в приватном `compass.db.absolut-credentials.json`, исключённом из Git. Терминал пароль не печатает, прежние сеансы не отзывает.

## Данные сценария

- Вымышленная пациентка 36 лет: личные данные, измерения, жалобы, шестимесячная история тревоги, сон, работа, привычки, поддержка, репродуктивный анамнез, цели и опасения. Все применимые вопросы разделов отвечены; скрытые ветви не заполняются.
- Восемь связанных карточек: заболевание, три лекарства, реакция, посещение, обследование и семейное сведение; одна запись семейного дерева. Анамнез отправлен врачу. Реальных документов и лабораторных результатов нет; отсутствующий файл не выдаётся за проверенное заключение.
- F41.1 — заданное вымышленное врачебное условие, не диагноз модели. Возраст согласован внутри сценария; сопутствующие факторы и лекарственная аллергия имеют явные отрицательные записи. Это не проверка реального человека.
- **30 дней дневника:** сон, качество сна, самочувствие, отдельная шкала тревоги, рабочие события.
- **Девять завершённых анкет:** PHQ-4 **8 → 6 → 3**, GAD-7 **16 → 12 → 7**, PHQ-9 **12 → 9 → 5**. Последний вопрос PHQ-9 имеет нулевой ответ. Искусственные ответы не доказывают эффект лечения.
- Авиандр: исходная вымышленная текущая терапия с 11-го дня; за 20 дней **19 отметок приёма и 1 пропуск с причиной**, нет неуточнённых дней. Первые десять дней не считаются пропусками. Дозировка не задаётся.
- Эсциталопрам — исходное условие сопутствующей терапии для проверки пары; Спитомин — завершённая до окна терапия. Это не рекомендация сочетания или назначения.
- Кратковременная тошнота: сообщение пациента отдельно от вымышленной врачебной оценки «возможная связь». Указано альтернативное объяснение — нерегулярное питание. Оценка видна пациенту, причинность не установлена.
- Отправлены три пожелания: избежать сонливости, тошноты и увеличения массы тела; главный приоритет — сонливость.

Окно привязано к первому запуску по Москве. Повтор не сдвигает историю; новые наблюдения добавляйте через интерфейс. В лекарственных карточках доза остаётся незаполненной намеренно, поэтому их индикатор не достигает 100%.

## Ручная проверка

1. Откройте карту у выбранного специалиста; другой врач доступа не имеет.
2. Проверьте четыре вывода, по три основания, вопросы и «Подробнее». Цифры вычисляются из базы, готовые ответы модели не добавляются.
3. Раскройте «Исходные анкеты и сведения карты»: девять анкет, ответы, текущая и прежняя терапия. Сравните суммы с графиками.
4. Проверьте переносимость: 19/1/0/0, сообщение о тошноте и отдельное врачебное уточнение. В назначениях и пациентском профиле доступна отправленная учебная схема и пожелания.
5. Сохраните новое уточнение или анкету: карточки должны пересчитаться обычным способом. Изменения не подменяются повторным чтением сценария.
6. Повторите команду: карта, пароль и новые записи должны сохраниться без повторных заполнений.

## Границы полноты

Заполнены данные пациента и история наблюдений. Четыре направления, графики и вопросы рассчитываются из записей. Поддельные проверенные источники, клинические правила и готовые результаты модели не создаются. В исходной базе нет действующих проверенных правил Авиандра: медицинские статусы могут оставаться «Недостаточно проверенных данных» при подробно заполненной карте. Ваши действующие источники используются обычным способом; команда их не меняет.

Медицинское сопоставление требует настоящего проверенного источника и отдельной проверки правил врачом в «Проверенные источники и правила». Регистрационные метаданные не заменяют инструкцию. Проверка полноты и причинности остаётся отдельной задачей.

Текст модели появляется после запуска Ollama кнопкой **«Объяснить этот расчёт с помощью ИИ»**; общая сводка — **«Проанализировать эту карту»**. Команда создания не запускает модель и не меняет лечение. [Запуск Ollama и worker](AVIANDR_RESEARCH.md#запуск-приложения-и-настоящей-локальной-модели).
