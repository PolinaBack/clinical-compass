# Сообщения о реакциях внутри лекарственной схемы

## Обновление в PyCharm

Остановите сервер. В терминале проекта:

```powershell
git switch feat/local-mvp
git pull --ff-only origin feat/local-mvp
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Используйте прежний `COMPASS_DB`, если он задан. Обновите страницу Ctrl+F5. Пересоздавать БД, запускать `setup_demo` или менять пароли не нужно. Миграция `017_medicine_reactions.sql` добавит три таблицы и вспомогательный уникальный индекс без изменения существующих записей.

## Врач: схема и реакции

1. Откройте **Пациенты → нужная карта → Назначения → Лекарства**.
2. Заполните и сохраните учебную схему. Для ещё не сохранённого препарата сообщается, что сначала нужна сохранённая версия.
3. Внутри нужного препарата раскройте **Зафиксировать реакцию у пациента**. Выберите проявление из реестра этого препарата или «Другая реакция / описать своими словами».
4. При необходимости задайте дату начала, выраженность, текущее состояние, описание и врачебную оценку связи. Для оценки, отличной от «пока не оценена», нужно основание. Поля не подбирают лечение автоматически.
5. Нажмите **Сохранить реакцию**. Запись появится в этом препарате с датой, происхождением «Запись врача», версией схемы и сохранённой дозой.

До отправки схемы запись видит только специалист. Если версия уже отправлена, можно отдельно отметить **Показать эту запись пациенту**. По умолчанию врачебная запись остаётся закрытой. Последующая отправка схемы не раскрывает ранее сохранённые закрытые записи.

После сообщения пациента врач видит его в том же препарате с пометкой **Со слов пациента**. Можно раскрыть **Добавить оценку или уточнение**, указать связь и комментарий. Оценки дописываются в историю, исходное сообщение не перезаписывается. Видимость оценки пациенту включается отдельной отметкой; закрытая врачебная запись не становится публичной через оценку.

## Отдельная отправка схемы

Ранее пациент видел только пустое лекарственное состояние, потому что схемы были личными черновиками. Для нового пациентского сообщения нужен конкретный препарат, который врач действительно открыл пациенту.

После сохранения внизу лекарственного блока находится **Отправить учебную схему пациенту**. Это отдельное явное действие. Оно передаёт только сохранённые поля схемы и комментарий пациенту, без закрытых реакций, личных черновиков и контекста подбора/пожеланий. Повторная отправка той же версии не создаёт дубликат. При изменении схемы сначала сохраните новую версию, затем отправьте её отдельно.

Схема остаётся учебной, не является рецептом и не подписывается. Непереданный черновик не появляется у пациента автоматически.

## Пациент

1. Откройте **Профиль → Мои назначения и обследования → Лекарства**.
2. Найдите препарат в последней отправленной специалистом учебной схеме.
3. Внутри карточки раскройте **Сообщить о побочном эффекте**.
4. Выберите предполагаемую реакцию или опишите свой вариант. Необязательно указывать точную дату, если она неизвестна. Укажите, как сильно мешает проявление, сохраняется ли оно, и при необходимости добавьте описание.
5. Нажмите **Сообщить врачу**. Сообщение появится в карточке препарата и будет видно ведущему специалисту. В его списке пациентов появится событие без текста сообщения.

Само сообщение не устанавливает причинную связь с лекарством. Пациент не может выставить врачебную оценку. Записи не меняют дозу, не отменяют препараты и не превращают сообщения в подтверждённые общие побочные эффекты библиотеки.

Немедленный ответ не гарантируется; из формы доступен существующий раздел срочной помощи. Email, SMS, push и отправка в органы фармаконадзора не подключались.

## Версии и доступ

- Сообщение связано с пациентом, препаратом, конкретной сохранённой версией схемы и дозой. Изменение схемы не переписывает прежнюю реакцию.
- После новой отправки прежние схемы остаются в раскрывающейся истории. Для препарата с прежними сообщениями есть ссылка к ним. Пациент может сообщить и о реакции на ранее отправленную версию.
- Врач видит сообщения по коду препарата, включая прежние версии. Сообщения по убранным из текущего черновика препаратам доступны в «Реакции по ранее сохранённым препаратам».
- Другая карта не получает чужую схему или сообщения. Сервер проверяет роль, актуальный аккаунт, ведущего врача, принадлежность схемы, версии и наличие препарата. Пациенту доступна только явно отправленная версия и открытые записи.
- Все три новые таблицы неизменяемы: сообщения и оценки дописываются, прежние данные не удаляются. Новая оценка может уточнять прежнюю.
- Снимки и тексты зашифрованы прежним Fernet-ключом. Резервная копия сохраняет этот ключ вместе с БД. При утрате ключ не заменяется новым поверх зашифрованных записей.

## Ручная проверка

1. Сохраните вымышленную схему с двумя препаратами. До отдельной отправки пациент не должен видеть её.
2. Запишите закрытое наблюдение врача. Отправьте схему пациенту: препарат появляется, закрытое наблюдение не раскрывается.
3. В пациентском браузере выберите реакцию из списка, укажите дату и описание, отправьте. Проверьте сообщение у обоих участников, источник и исходную дозу.
4. Врач добавляет закрытую оценку: пациент её не видит. Добавляет отдельную открытую оценку: пациент видит её после обновления.
5. Врач фиксирует собственное наблюдение по другому препарату, явно отмечает показ пациенту. Проверьте происхождение «Запись врача».
6. Измените дозу/состав схемы и сохраните. Это не должно менять сообщения или отправленную ранее схему. После новой отправки проверьте историю и прежнюю дозу в реакции.
7. Откройте другую карту: в ней нет этих сообщений. Пациент не может отправлять сообщения по неотправленному черновику, другому препарату или выставлять врачебную оценку.
8. Перезапустите сервер: схемы, сообщения и оценки остаются. Проверьте телефон: формы раскрываются внутри соответствующего препарата.

## Границы проверки

Автоматические тесты и Chromium используют вымышленные записи. Они не подтверждают клиническую причинность реакций, полноту справочника и безопасность лекарств. Windows/PyCharm и реальные клинические сценарии требуют отдельной ручной проверки. Запрос не вводит автоматический подбор лекарства, изменение лечения или внешний фармаконадзор.
