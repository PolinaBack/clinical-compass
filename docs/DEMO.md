# Сценарий демонстрации обновления

Только вымышленные сведения. Сначала `python -m scripts.setup_demo`, сохранить сгенерированные пароли. При необходимости `seed_demo` — только до заполнения любых форм. Для одновременной работы используйте два независимых окна браузера.

1. Главная: два входа, FAQ и помощь без регистрации. Пролистать горизонтальный блок «Полезно каждому пациенту» кнопками «Назад»/«Далее», клавиатурой или свайпом. Показать, что карточки не требуют анкет.
2. Войти в `patient-a` через «Я пациент». До участия анкеты недоступны; прочитать фактические правила. Подтвердить только синтетическую демонстрацию и возраст 18+.
3. Начать PHQ-4. Добавить комментарий и «! Хочу обсудить». Показать паузу, отказ и отсутствие стандартного итога неполной формы. Для продолжения теста заполнить 1,2,1,2 — обе подшкалы по 3. Это синтетический пример, не клинический профиль.
4. Войти отдельным окном в `specialist`. Видны только его пациенты. В карточке есть предложения PHQ-9/GAD-7. Подтвердить их назначения. Увидеть исходный комментарий: прочтение снимает «Новое», но «! Обсудить» закрывается отдельно.
5. Пациент заполняет PHQ-9. Для проверки реакции — восемь нулей и 1 в пункте 9. Сохранить черновик: событие уточнения появится независимо от малой суммы. Показать «Мне нужна помощь сейчас» и отсутствие обещания реального дежурного.
6. Врач: событие получено кабинетом → подтвердить → записать синтетическое действие. Это отдельные состояния, не имитация уже оказанной медицинской помощи.
7. Завершить PHQ-9/GAD-7; показать отдельные линии, исходные ответы по точке и PHQ-ADS одной сессии. Изменить ответ и открыть историю. Неполная анкета не превращается в 0.
8. По назначению открыть HCL-33: контекст перед/после симптомов, только 33 симптомных ответа в сумме; нет диагноза БАР или неподтверждённого порога.
9. При поддержке браузера записать синтетическое пояснение с отдельным согласием. Прослушать исходник; показать, что без расшифровки запись доступна, а баллы не изменены. При отказе микрофона текст остаётся рабочим.
10. Показать дневник, переписку, генограмму. Пациент не может открыть кабинет специалиста или карточку другого пациента. Для другого аккаунта требуется выход и новый вход.
11. Врачебные MADRS/HDRS и C-SSRS: показать честный статус «нужны критерии/официальная форма», без фиктивных баллов. Справка по «Авиандру» доступна специалисту вместе с PDF и статусом актуальности.
12. Перезапустить сервер и снова войти: записи сохраняются. Создать резервную копию. Все проверки выполняются на синтетической базе.

Реальные клинические сценарии назначения «Авиандра» и маршрутизации ещё требуют актуальных проверенных документов. Технический сценарий не выдаётся за выполнение этих клинических условий.
