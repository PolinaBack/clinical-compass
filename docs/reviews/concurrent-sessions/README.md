# Приёмка U-CONCURRENT-SESSIONS-25 · 25.10.2026

Ветка `feat/local-mvp`, сравнение с `d29b46b`. Исправление сеансов без изменения данных, паролей, медицинских алгоритмов и интерфейса кабинетов.

## Причина и результат

Два независимых браузера уже могли входить под одним аккаунтом внутри одного процесса. Воспроизведён сбой при передаче cookie второму экземпляру приложения: каждый `create_app` имел свой случайный ключ, поэтому вход превращался в анонимный, а POST/выход с прежним CSRF-токеном мог завершиться 403. Отдельно воспроизведён 403 при повторном выходе из уже закрытого сеанса. До исправления два соответствующих теста падали; три исходных проверки независимых браузеров/CSRF проходили.

Теперь ключ постоянный для выбранного файла базы. Создание атомарно публикует полностью записанный приватный файл без замены ключа другого процесса; несколько первых процессов получают один ключ. Настраиваются общий приватный файл или секрет окружения. Некорректный файл не перезаписывается и не заменяется случайным запасным ключом. Новые секреты исключены из Git.

Каждый браузер сохраняет собственный CSRF-токен и cookie. Выход завершает только его сеанс; повторный выход не требует уже потерянного токена, если активного входа больше нет. Авторизованный выход, остальные POST, объектные права, контроль версий и отзыв по `auth_version` сохраняют проверки. Это не отключение 403 для настоящего запрета доступа.

## Обновление и границы

После обновления и перезапуска нужен один новый вход, поскольку прежний случайный ключ не сохранялся. Затем обычные рестарты сохраняют действующие сеансы с прежним сроком cookie. Очистка БД, миграция аккаунтов и смена паролей не требуются.

Обычные вкладки одного профиля браузера разделяют cookies: выход распространяется на эти вкладки. Для независимой проверки используются разные устройства, браузеры или обычное/приватное окна. Настоящие запреты чужого доступа/CSRF и конфликты одной версии формы не скрываются. Это исправление не вводит слияние одновременных правок и не меняет аудит: при общем логине автором по-прежнему является один аккаунт.

Проверены Linux/Chromium и локальная файловая система. Windows/PyCharm и сетевые диски вручную не запускались; NTFS поддерживает используемую публикацию жёсткой ссылкой. Для файловой системы без неё предусмотрена явная настройка общего секрета, без перехода к разным случайным ключам процессов.
