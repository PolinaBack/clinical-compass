# Оформление первичного анамнеза по образцу пользователя

Основа — опубликованный коммит пользователя `320c120 corrections` в feat/local-mvp. Его изменения scales/assessment/diary/safety сохранены. В этом изменении не запускаются новые этапы и не меняется main.

| Пожелание | Проверка |
|---|---|
| Пастельные карточки с прежним содержимым | Общая сетка 3/2/1 колонка; те же 16 категорий/155 вопросов и 7 типов связанных карточек/89 полей, без сокращения содержания |
| Вводный текст перед прогрессом | Проверяется порядок DOM и фактическое положение в Chromium |
| Проценты без общего числа вопросов | Сервер, autosave и перезагрузка используют число отвеченных вопросов; 100% только при полном заполнении |
| Пояснение доступа внизу | После карточек, действий отправки и остальных сведений |
| Убрать прежние свободные заметки | Блок и формы отсутствуют у обеих ролей; исходные записи patient_profiles сохранены |
| Цикл только при женском поле | Карточки, список переходов, прямой GET и сохранение проверяют пол; смена пола не стирает черновик, старые версии читаются по собственному снимку |
| Красивее и короче внутри | Компактные поля без повторных подписей, дополнительные вопросы/статусы/вложения по нажатию, пустые связанные блоки не отображаются |
| Удобный выбор раздела | Сохранение текущей формы перед переходом, задержанный autosave, обычный POST без JS/клавиатура; недоступная цель/старый revision не перезаписывают ответы |

Браузерный сценарий: `scripts/browser_intake_redesign.py`, вызывается с уже вошедшими пациентом и врачом **на отдельной временной базе**. Для axe нужен `COMPASS_AXE_PATH` с локальным `axe.min.js`. Серверные сценарии — `tests/test_intake_layout.py` и обновлённые тесты анамнеза. Рабочие данные и пароли не включаются в скриншоты или отчёты.

Chromium: 320/390/768/1280 px, обе роли, восемь автоматических axe WCAG A/AA проверок без нарушений, без ошибок JavaScript. Проверена компактность страницы Личных данных: менее 2000 px по высоте на 1280 и менее 2500 px на 390 (включая шапку и подвал). Это не сертификация доступности и не запуск настоящего Windows.

Скриншоты: [карточки на компьютере](overview-1280.png), [карточки на телефоне](overview-390.png), [Личные данные на компьютере](personal-1280.png), [Личные данные на телефоне](personal-390.png).

`browser.txt` и `accessibility.json` — новый сценарий и 8 проверок axe. `browser-regression.txt` и `regression-accessibility.json` — прежний полный сценарий анамнеза/голосовой заметки/вложений/проверки врачом/вопросов дневника и ещё 20 проверок axe. Всего 28 автоматических проверок без нарушений.

`data-check.json` подтверждает неизменность всех прежних 551 строк в 71 таблице после перезапуска (резервная копия вне Git), `requirements-check.json` — всех 806 исходных ID/формулировок/приоритетов/зависимостей/этапов. `targeted.txt` и `layout-tests.txt` содержат пройденные целевые серверные сценарии, `pytest.txt` — полный набор. [Результаты и публикация](../../PROGRESS.md), [инструкция PyCharm](../../ANAMNESIS_DESIGN.md).
