# Плашка запросов после сохранения справки

27.10.2026 · U-EXTRACT-REQUEST-NOTICE-27.

Счётчик главной страницы врача теперь относится к обращениям, ожидающим внимания, по последнему событию запроса. Ответ/начало оформления/сохранение связанного документа исключают обработанный запрос; новое уточнение пациента по незавершённому запросу возвращает его. При нуле плашка полностью отсутствует. Полный список запросов, документы и неизменяемая история сохраняются.

**16 passed, 1 warning, 26,64 с** — `tests/test_extract_request_notice.py` и `tests/test_patient_extracts_direct.py`. Шесть новых сценариев проверяют пустой кабинет/несколько запросов/чужого врача, сохранённый ответ «В работе», уточнения пациента, завершение, открытие запроса без подтверждения, неизменность счётчика при ошибке/предпросмотре/конфликте. Пять способов работы с документом — сохранение, сохранение с печатью, публикация, обновление сведений, подтверждение быстрой печати — подтверждают обработку только связанного запроса после успешной записи. Черновики не становятся опубликованными, прочие запросы остаются видимыми.

Десять прежних сценариев проверяют источник данных без личного черновика, редактор/предпросмотр/подтверждение, публикацию/снятие, роли, параллельные формы, обновление источников, шифрование и неизменяемые версии. Предупреждение — прежний deprecated alias Starlette/AnyIO.

Проверки вызывают реальные обработчики/парсинг форм/шаблоны и работают с временными SQLite-базами. HTTP middleware и новый браузерный прогон здесь не выполнялись. Python compilation и `git diff --check` прошли. Рабочая БД/пароли и все 806 исходных строк/ячеек требований сохранены; схема не менялась. [Инварианты](invariants.json).

[Как работает](../../PATIENT_EXTRACTS.md). После обновления ветки перезапустить веб-сервер; отдельные обработчики и миграция не нужны.
