# Приёмка обновления Авиандра и привязок пациентов

25.10.2026 · исходный коммит `7d88665`, ветка `feat/local-mvp`. U-AVIANDR-LIVE-25, U-DEMO-ROSTER-25.

## Причины и исправление

Открытый экран прежде не получал новые данные до повторного GET. В выводе использовались только две полные шкалы, поэтому новая PHQ-4 могла остаться незаметной при наличии GAD-7/PHQ-9. Сейчас отдельный read-only API пересчитывает актуальную карту с текущим контролем ведущего врача и согласия. Неизменный checksum не передаёт HTML; обновление не запускает модель, не записывает снимки или назначения. Клиент проверяет карту раз в пять секунд при видимом окне и на возврате к нему. Читаемая часть заменяется отдельно от редактируемых форм врача; раскрытия, фокус, положение и ссылки на факты сохраняются. При выделении текста замена откладывается. Ошибка связи повторяется автоматически, отзыв доступа останавливает цикл. Без JS остаётся обычная кнопка GET.

В выводе отображаются все три поддержанные полные шкалы и текущие незавершённые формы как число ответов. Черновые ответы не становятся окончательным баллом. Заголовок показывает последнюю отправленную версию анамнеза; личный черновик до отправки не публикуется. Старое объяснение Ollama скрывается при изменении данных. Статус медицинской неопределённости может сохраняться при обновившихся фактах — без проверенного правила он не становится положительным.

Прежний явный reset переиспользовал A/B под C/D, сохраняя логины. Новая добавляющая команда с копией/ключом и транзакцией восстанавливает раздельные A/B у специалиста 1, C/D переводит к специалисту 2, E не переносит. Существующие карты/владельцы используются повторно, недостающие A/B создаются пустыми, недостающие отдельные аккаунты получают случайные пароли. Старые хеши паролей и авторство клинических данных не меняются. При смене карты аккаунта прежние сеансы отзываются. Коллизии не объединяются автоматически; повтор не создаёт дубликатов. CLI подготовки C/D/E также применяет это распределение.

## Рабочая демобаза

Изменение явно разрешено последующим сообщением пользователя о распределении. A/B восстановлены на новых ID 4/5 у специалиста 1; C/D сохранили ID 1/2 и переданы специалисту 2; E остался на ID 3 у специалиста 2. Старые пароли сохранены, недостающие `patient-c`/`patient-d` созданы отдельно, их пароли находятся только в приватном локальном файле вне Git. **Все исходные клинические строки, 90 дневников и 27 анкет сохранены.** Созданы полные резервные копии с ключом; повтор не меняет строки и не дублирует карты. Integrity/FK и актуальные права обоих врачей проверены. [Результат без паролей](working-roster.json).

БД в PyCharm пользователя обновляется отдельной командой по [инструкции](../../AVIANDR_REFRESH_AND_ROSTER.md); `git pull` не переносит рабочую БД разработчика. Новых миграций и зависимостей нет.
