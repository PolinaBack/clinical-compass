# Общий внешний вид анкет пациента и врача

U-QUESTIONNAIRE-DESIGN-24. Карточки и ответы оформлены по первичному анамнезу и двум снимкам пользователя: светлые панели, округлые варианты, сиреневое выделение с галочкой, понятный статус ответа. Компьютер — три колонки карточек, планшет — две, телефон — одна.

Пациент выбирает нативный переключатель и сохраняет прежней кнопкой. «Ответ выбран» не подменяет серверное подтверждение сохранения. Пропуск/откладывание/отказ отделены от нуля. Врач видит исходный ответ тем же оформлением, без элементов редактирования за пациента. Контекст HCL остаётся отдельно от суммы. Параметры сессии/срока назначения находятся в компактном раскрытии; обычное назначение по-прежнему доступно одной кнопкой.

В существующем шаблоне были повреждены открывающие теги вариантов и атрибуты checked/open: браузер получал часть атрибутов как текст. Исправлена разметка; названия полей, значения, POST, CSRF, revision, request_id и клинические события сохранены. Источники вопросов, баллы, ветвление, доступ, история, состав библиотеки и все 806 требований не изменялись. Серверные Python-файлы и схема SQLite не менялись.

## Проверки

- Полный pytest: **362 passed**, 581,02 с, exit code 0; одно прежнее предупреждение зависимости. [Журнал](pytest.txt).
- Целевые шкалы/потоки/адаптация безопасности/каталог: **57 passed**, exit code 0. [Журнал](targeted.txt).
- Chromium: настоящий выбор и POST/перезагрузка, ноль/отложено/отказ, комментарий/обсуждение, ветвление безопасности и дополнительный вопрос о недавнем поведении, назначение PHQ-ADS, все вопросы PHQ-9/GAD-7/HCL-33, отдельный контекст, событие PHQ-9 п.9 при общей сумме 1, запрет пациенту врачебного доступа и отсутствие правки исходных ответов врачом. Нативный POST без JS; проверка обязательной даты раскрывает её поле. [Сценарий](browser.txt).
- Прежний анамнез: добавление/редактирование/перезагрузка, связанные счётчики, файлы/подтверждение удаления, частный черновик и неизменяемая версия врача, неизвестные ответы без потери заполненного, переходы без JS. [Журнал](browser-regression.txt).
- Обе роли на 320/390/768/1280 px, без горизонтального переполнения и ошибок JavaScript. **32 axe WCAG A/AA проверки, 0 нарушений**: [анкеты](accessibility.json), [прежний анамнез](regression-accessibility.json). Клавиатура и сохранение без JS проверены отдельно; axe не является полной ручной проверкой screen reader.
- Рабочая SQLite после перезапуска: **71 таблица, 551 запись**, все исходные поля/строки и схема совпали с резервной копией; integrity_check=ok, foreign_key_check=[]. [Результат без содержимого базы](data-check.json).
- **806 ID**, формулировки, приоритеты, зависимости и этапы сохранены; исходные вопросы/варианты/баллы/ветвления/маршруты и схема совпадают с базовым коммитом. [Сравнение и хеши](requirements-check.json).

Все браузерные проверки используют отдельные временные базы и синтетические аккаунты. Настоящий Windows/PyCharm и локальные ИИ-модели в этой задаче не запускались. Миграции и повторное наполнение базы не нужны.
