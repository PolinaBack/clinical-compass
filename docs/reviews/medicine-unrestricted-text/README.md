# Проверка сохранения длинного текста

26.10.2026 · U-MEDICINE-TEXT-26. [Обновление и ручная проверка](../../MEDICINE_TEXT_STORAGE.md).

**29 passed**, одно прежнее предупреждение Starlette/AnyIO, 67,04 с. Команда: `.venv/bin/python -m pytest -q tests/test_medicine_unrestricted_text.py tests/test_doctor_medicines.py tests/test_medicine_card_lifecycle.py`.

Новые проверки воспроизводят точную причину скриншота: длинные метаданные при коротком названии. Форма сохраняется как `application/x-www-form-urlencoded` и `multipart/form-data` с текстовым полем больше 1 МБ. Проверены буквальное равенство данных после чтения из БД, пробелы/переводы строк/пустой МНН, отсутствие обрезки концов текста и сохранённый полный извлечённый текст. Цепочка HTTPS-адаптер → HTML/JSON-LD-разбор → редактируемая форма → явное сохранение использует маркированный синтетический транспорт. Проверены метаданные >500, раздел >15 000, группа >300, общий текст >20 000 символов.

Произвольная подпись ресурса и строка URL длиннее 2000 принимаются при сохранении; JavaScript/file-схемы остаются текстом без активной ссылки. В редакторе проверены многострочные элементы, отсутствие `required`/`maxlength` для всех полей содержимого. Прежние тесты каталога/ролей/CSRF/идемпотентности/неполных карточек/удаления/назначений прошли в том же прогоне.

Рабочая БД побайтно сохранена, миграций/сброса/смены паролей нет; все 806 исходных строк и ячеек требований неизменны. Новый браузерный прогон, нативный Windows/PyCharm и успешное чтение конкретного внешнего медицинского сайта не выполнялись. Проверки публичного HTTPS и размера фактической загрузки сайта остаются; это отдельная операция от сохранения карточки.
