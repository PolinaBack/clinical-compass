# Приёмка U-AVIANDR-RESEARCH-25 · 25.10.2026

Ветка `feat/local-mvp`, исходная точка `d6f5712`. Исследовательский модуль в существующем «Анализе ИИ». Все новые сценарии и проверки используют полностью синтетические данные. Это техническая приёмка, не подтверждение клинической эффективности или диагностической точности.

## Реализовано

- Четыре независимых направления Авиандра: показания, противопоказания, конкретные сочетания и фактическая переносимость. Мятная диаграмма статусов и нативные раскрытия, сведения именно выбранного пациента, основания/источники/ограничения и 3–7 вопросов по пробелам. Нет общего процента пригодности.
- Действительно читаются отправленный анамнез, исходные ответы и история анкет, дневник, врачебные уточнения, текущая терапия с отдельной идентификацией, сообщения о реакциях и последние отправленные пожелания с главным приоритетом. Частные черновики не становятся действующим назначением. Противоречащие подтверждённые сведения требуют уточнения.
- Дневные отметки связаны с отправленной версией конкретного препарата. История неизменяема, повторная отправка идемпотентна. Дни до начала исключены из периода приёма, отсутствие записи не становится пропуском. Реакция пациента, наблюдение врача и оценка связи разделены; временное совпадение не устанавливает причинность.
- Python рассчитывает статусы по типизированным правилам, связанным с активным проверенным источником/РУ/разделом/цитатой. Отзыв/замена/истечение источника исключает правило из следующего расчёта. Неполная библиотека не даёт заключения о безопасности. Смысл соответствия предиката цитате проверяет врач.
- Настоящие локальные `/api/show` и `/api/chat` Ollama, отдельная очередь с lease/heartbeat, зашифрованные снимки, проверка ролей/версий до и после вызова, источников и актуальности данных. Строгая структура сводки/четырёх объяснений/вопросов/противоречий, допустимые ID оснований и пробелов, ограничение опасных утверждений; статусы и назначения модель не меняет.
- При ошибке/невалидном ответе текст отсутствует, видны причина и текущий программный расчёт. Обновление объяснения — настоящий GET, работает без JavaScript. Старые объяснения не выдаются за актуальные после изменения данных/источников.

Присланный [регистрационный фрагмент ГРЛС](../../inputs/2026-10-25/aviandr-grls-registration-excerpt.txt) содержит РУ, держателя, даты и химическое наименование. Производитель обрывается и не дописан. Прямой ссылки/полной инструкции нет; онлайн-сверка здесь не состоялась. Метаданные **не создают медицинских правил**. Изначально `aviandr_rules=0`; неопределённые клинические статусы C/D/E ожидаемы. Технические цитаты/пары в тестах явно вымышленные и не входят в поставленную базу как подтверждённые свойства лекарства.

После успешных тестов выполнена [явная замена рабочего файла](workspace-reset.json): все те же исходные строки проверены в архиве, новый файл содержит ровно три пациента C/D/E, двух врачей, 90 дневников, 27 заполненных анкет. Первый врач видит C/D, второй — E. Контроль целостности и внешних ключей пройден, повторный запуск без сброса не меняет данные.

Основные `specialist`, `patient-a`, `patient-b` сохранили хеши паролей. Новые `specialist-2` и `patient-e` получили случайные пароли, сохранённые в локальном игнорируемом файле с ограниченными правами. Все новые аккаунты имеют версию авторизации выше любого старого аккаунта: старые сеансы недействительны даже при совпадении числовых ID. Ключи, DB и пароли не включены в Git. Отдельный файл на компьютере пользователя этим не заменяется. Однократная команда `--reset`, резервная копия и последующие обычные запуски описаны в инструкции. Повтор с `--reset` намеренно снова очищает выбранную базу; без этого флага добавление идемпотентно и сохраняет ручные изменения.
