## Открыть в PyCharm

Остановите приложение и ИИ-обработчик, затем в терминале корня проекта:

```powershell
git switch feat/local-mvp
git pull --ff-only origin feat/local-mvp
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Новых зависимостей или миграций нет. **Сброс БД для обновления экрана не требуется.** Данные C/D/E не перезаписываются, новые пациенты при открытии экрана не создаются.

Войдите специалистом: **Пациенты → выбранная карта → Анализ ИИ → Авиандр — клиническая применимость**. Прямой адрес имеет вид `http://127.0.0.1:8000/patients/НОМЕР_КАРТЫ/ai-analysis#aviandr`. Первый специалист видит свои C/D, второй — E; номер карты зависит от ранее созданной базы. При необходимости обновите страницу Ctrl+F5.

Если сценарии C/D/E ещё не создавались, их можно добавить без очистки:

```powershell
.\.venv\Scripts\python.exe -m scripts.setup_aviandr_scenarios
```

Команда без `--reset` идемпотентна: существующие сценарии и ручные изменения остаются. Пароли недостающих новых аккаунтов выводятся только при их создании. Не используйте reset ради изменения оформления.

## Что видно сразу

На компьютере — четыре карточки 2×2; на телефоне — одна колонка. В каждой открыты статус, вывод по пациенту из 2–4 предложений, три конкретных основания, основное неизвестное сведение и два вопроса врачу. «Подробнее» раскрывает все ограничения/вопросы, записи и проверенные медицинские источники, если они есть. Цвет относится к независимому статусу, общего процента нет.

По последнему визуальному примеру добавлены разные круглые значки направлений, компактные статусы, мягкие цветовые акценты и разделение оснований/вопросов на две колонки внутри широкой карточки. Под четырьмя карточками графики расположены слева, вопросы и локальное объяснение справа; на узком экране блоки последовательно переходят в одну колонку. Сохранена существующая навигация кабинета — новых неработающих пунктов из макета нет. Название пациента и все значения берутся из выбранной карты, не копируются с картинки.

Ссылки у оснований ведут к исходному факту с ID; при включённом JavaScript нужное раскрытие открывается автоматически. Оттуда доступны анкета, профиль, дневник или назначения. Нативное «Подробнее» и формы работают без JavaScript.

Ниже карточек находятся три графика дневника — субъективная тревога, самочувствие, сон — и графики полных PHQ-4/PHQ-9/GAD-7 по датам одной версии. Пропуски остаются пропусками, линия разрывается; значения не дорисовываются нулями. Субъективная тревога берётся из сохранённого показателя дневника, явно названного тревогой со шкалой 0–10. Это существующее правило чтения карты, не диагностическая интерпретация. Для нескольких записей одного дня используется последняя запись и её показатели.

Далее идут 3–7 вопросов по карте, текстовый ИИ, ограничения/источники, регистрационные сведения и прежние формы врачебного уточнения/проверенных правил. Общий ИИ-анализ карты сохранён отдельно на той же странице.

## Python и Ollama

| Возможность | Без Ollama | С локальной Ollama и worker |
|---|---|---|
| Статусы по четырём направлениям | Да, прежний проверяемый расчёт | Модель не меняет статусы |
| Индивидуальные выводы, основания, неизвестные сведения | Да, функции Python читают текущую карту | Естественный пересказ переданного контекста |
| Вопросы врачу | Да, по конкретным пробелам | Дополнительная формулировка вопросов с допустимыми gap ID |
| Графики и фактический приём/пропуски/реакции | Да | Передаются как факты, без установления причинности |
| Краткая текстовая сводка и поиск противоречий моделью | Нет, не имитируются | Структурированный ответ с ID оснований, проверяемый сервером |

Новый `aviandr_narratives.py` содержит отдельные функции показаний, противопоказаний, сочетаемости и переносимости. Они формулируют вывод из фактов/статуса, не определяют новые медицинские свойства. В анамнезе различаются сообщённое и проверенное врачом; отрицательный ответ и отсутствие записи не смешиваются. Текст не выбирается по буквам C/D/E — те же функции работают для любой доступной карты, включая пустую и заполненную вручную.

Если проверенной инструкции/правила нет, карточка всё равно описывает жалобы, анкетные суммы, текущую терапию, наблюдения и конкретный пробел. Скрининг не становится диагнозом. Неизвестная пара не получает взаимодействие из редакционной матрицы. Подтверждённая запись приёма, назначенная схема и неподтверждённое сообщение остаются разными состояниями. Дни до начала не входят в приверженность; пропуск, «не знаю» и отсутствие записи разделены.

Ollama получает четыре Python-вывода, неизвестные сведения, факты пациента, прежний ограниченный контекст карты и допустимые ID. Для каждого пояснения сервер требует хотя бы один факт `patient_data` именно этого направления; ссылки только на общую фразу об отсутствии инструкции недостаточны. Вопросы привязаны к допустимым пробелам, противоречия и сводка — к основаниям. Лишние поля статусов, чужие/выдуманные ID и ряд неподтверждённых лекарственных утверждений отклоняются. Это структурная проверка и консервативные текстовые ограничения, а не доказательство смысловой правильности свободного пересказа.

Для реальной генерации запустите установленную Ollama с `qwen2.5:3b` и отдельный терминал:

```powershell
.\.venv\Scripts\python.exe -m scripts.patient_ai_worker
```

Нажмите «Объяснить этот расчёт с помощью ИИ». Подробности установки модели, loopback-настройки и тайм-ауты остаются в [основной инструкции](AVIANDR_RESEARCH.md). В среде разработки успешная генерация настоящей моделью не проверена: Ollama отсутствует. Настоящий HTTP-отказ worker проверен; успешный структурированный протокол проверяется отдельно через явно обозначенный тестовый транспорт.

## Актуальность

Заголовок показывает время текущего расчёта по Москве. Само время открытия не входит в хеш снимка: простое обновление страницы не делает объяснение устаревшим.

Расчёт выполняется заново на GET. После сохранения врачебного уточнения он обновляется при возврате на экран. После изменения из другого окна нажмите «Обновить расчёт по карте»: будут прочитаны актуальные отправленный анамнез, препараты, анкеты, дневник, приём/реакции и отправленные пожелания. Частный черновик не считается отправленной информацией.

Изменение данных, проверенного источника или версии алгоритма делает прежний текст Ollama устаревшим: показывается предупреждение, прежний текст не выдаётся за текущий, Python-карточки остаются доступны. Для нового пояснения нужен новый запуск модели. Исторический снимок не перезаписывается.

## Проверить вручную

1. **C:** четыре вывода доступны при выключенной Ollama. Видны симптомы/полные суммы анкет и отсутствие подтверждённого диагноза; рассматриваемый препарат не превращается в фактический приём. Переносимость неизвестна, предложены параметры наблюдения.
2. **D:** видны записанная сопутствующая терапия, отсутствие подтверждения МНН и ограничения анамнеза. Не должно появиться придуманное взаимодействие или вывод о безопасности. В браузерной технической проверке во временный D добавлено второе неподтверждённое средство; обе пары остаются неизвестными. Рабочие назначения ради этого теста не менялись.
3. **E:** до ручных изменений сценария — 16 дней после начала, 14 дней с отметкой/2 пропуска, тошнота и средние значения до/после. Причины пропусков и оценка врача показаны отдельно. Главный отправленный приоритет пациента виден в основаниях и вопросе. Нет утверждения, что лекарство вызвало изменение.
4. Нажмите ссылку у основания и «Подробнее», откройте исходную анкету/профиль. Сравните данные с текстом карточки и датами графиков.
5. На синтетической копии сохраните врачебное уточнение возраста или фактора: соответствующая карточка меняется. Новая отправленная подробность анамнеза, результат анкеты, сон последнего дня и текущий препарат также меняют соответствующий вывод.
6. У пациента E измените отдельную дневную отметку приёма на «Не могу уточнить». После обновления у врача станет 13 дней с отметкой/2 пропуска/1 неизвестный; схема лечения не изменится.
7. Если есть завершённое объяснение модели, затем измените карту: проверьте предупреждение об устаревании и сохранность текущих четырёх выводов. При отключённой Ollama новый запуск должен показать ошибку соединения, без готового текста модели; карточки остаются полными.
8. Врач C/D не должен открыть E, врач E — C/D; пациент не получает доступ к врачебному ИИ-разделу. Эти настоящие запреты 403 не относятся к исправленному одновременному входу в один аккаунт.
