# Как посмотреть изменения от 23 октября

## Обновить проект в PyCharm

В PyCharm откройте **Terminal** внизу окна. Остановите приложение и обработчик встреч в их терминалах клавишами **Ctrl+C**. Сначала сохраните резервную копию существующих данных:

```powershell
.\.venv\Scripts\python.exe -m scripts.backup data\backups\before-cabinet-2026-10-23.db
```

Если такая копия уже есть, укажите другое имя: скрипт специально не перезаписывает её. При наличии вложений он также копирует ключ рядом с базой. Для восстановления нужны оба файла.

Получите изменения именно своей рабочей ветки:

```powershell
git status
git switch feat/local-mvp
git pull --ff-only origin feat/local-mvp
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

`git status` показывает несохранённые локальные правки. Если переключение или получение изменений остановилось из-за них, сохраните свою работу и разберите сообщение Git. Не используйте `reset --hard` и не удаляйте папку `data`. `pull --ff-only` получает коммиты без переписывания истории. При запуске приложение само применяет миграцию **009** к существующей SQLite; заново создавать базу или запускать заполнение демонстрационными данными не нужно.

В браузере откройте **http://127.0.0.1:8000**. После перезапуска может потребоваться снова войти. Если браузер показывает старое оформление, нажмите **Ctrl+F5**. Выберите свой обычный аккаунт пациента или специалиста.

## Пациент: меню и анкета

Вход открывает **Дневник**. Сверху закреплена одна строка: **Дневник → Статистика → Материалы → Профиль → С чего начать → Настройки**. Раздел Материалы сохранён, чтобы получать назначенные статьи. Кнопка **Экстренная помощь** одна, справа вверху; она остаётся видна при прокрутке. В карточках дневника повторов нет. Во врачебном кабинете этой кнопки нет; клинические алерты продолжают работать отдельно.

Откройте **Профиль → Обо мне**:

- **Личные данные**: обращение, дата рождения и другие личные сведения.
- **Медицинские измерения**: рост в сантиметрах, масса в килограммах, дата/источник и изменения массы. Для взрослого пациента **175 см и 75 кг дают ИМТ 24,5**. Рядом показаны исходные рост/масса. При изменении поля старый расчёт скрывается до сохранения. Дата измерений может оставаться неизвестной; приложение не придумывает её. При ограничении врача, беременности и других предусмотренных условиях расчёт скрыт.
- Полоса на каждой карточке с вопросами отражает отвеченные видимые вопросы. «Не знаю», отложенные вопросы, комментарий, отметка «обсудить» и число файлов не превращаются в заполненные ответы. На странице сверху — доля завершённых анкет и поддерживающая фраза. Дерево без самостоятельных вопросов не включено в число анкет.

Проверка: заполните рост/массу, дождитесь «Черновик сохранён», обновите страницу. Значения и ИМТ должны сохраниться. Врач видит отправленную версию первичной анкеты после **«Отправить анкету врачу»**, а не личный черновик. Прежние отправки сохраняют свои формулировки и поля.

## Одно семейное дерево

В общем блоке первичной анкеты откройте **Семейное дерево**. Дублирующая вкладка семейной истории убрана. Нажмите лист родственника, заполните имя, возраст или заметку и сохраните: краткая информация появится на листе. Состояния добавляются в разделе **«Что известно»**.

Через **«Добавить близкого»** можно отдельно выбрать **брата**, **сестру** или **свою категорию**, например тётю. Мать и отец добавляются/редактируются через свои существующие листья. Создать ещё одну мать или отца нельзя, в том числе прямым запросом. Старые ошибочные дополнительные записи не удалены: при их наличии есть свёрнутый блок ранее созданных записей родителей. Старые текстовые семейные ответы также остаются в свёрнутом архиве на странице дерева.

Врач открывает **карточку пациента → Профиль → Обо мне → Родословная** и видит медицинскую схему из тех же данных. Квадрат — мужчина, круг — женщина, ромб — пол не указан. Есть поколения/номера, стрелка пробанда, отметка умершего. Врач выбирает сообщённое состояние над схемой; заливка показывает только сведения пользователя, вопросительный знак — недостаток сведений. Автоматических наследственных рисков нет. На узком экране сама схема прокручивается внутри своего блока.

## Врач: ресурсы и назначение чтения

В верхнем меню специалиста откройте **Ресурсы**. Общего пункта «Библиотека» больше нет. **Лекарства**, **Анкеты** и **FAQ-форум** доступны через **«Ещё»**; лекарственный справочник не удалён.

1. Найдите статью по названию или источнику. Добавлены все 12 присланных ссылок с вашими названиями.
2. Для собственной статьи раскройте **«Добавить свой ресурс»**, введите название и HTTPS-ссылку и сохраните.
3. На карточке раскройте **«Назначить пациенту»**, выберите своего пациента, при желании добавьте комментарий и срок, нажмите **«Назначить чтение»**.
4. В кабинете этого пациента откройте **Материалы**. Там появятся статья и комментарий врача. Открытие статьи отмечается отдельно; пациент может нажать **«Прочитано»** или **«Вернусь позже»**.
5. Врач видит состояние внизу страницы Ресурсов. Повторное назначение той же статьи тому же пациенту не создаёт дубль и не сбрасывает прочтение. Свои карточки другого врача и чужие назначения недоступны.

Ссылки ведут на внешние сайты. Проверка их текущей доступности из облака 23.10 была заблокирована сетевым шлюзом (CONNECT 403). Это не подтверждённые ошибки самих сайтов. Содержание, точные заголовки страниц и права на использование не объявлены проверенными; названия взяты из вашего списка.

## Итоги встреч без лишних переходов

Откройте **Профиль пациента → Консультации и видеосвязь** или у врача **«Итоги встреч»** в меню карточки пациента. В списке встреч сразу видны **«Итоги»** и **«Следующие шаги»**. Врач видит маркированный черновик; пациент — только опубликованную врачом версию. Подробная запись и проверка по-прежнему доступны врачу отдельной кнопкой. Приватные темы для врача, исходное видео и полная расшифровка пациенту не открываются.

Для новых расшифровок и итогов оставьте запущенным обработчик в **другой вкладке Terminal**:

```powershell
.\.venv\Scripts\python.exe -m scripts.meeting_worker
```

Эта доработка не требует переустанавливать Whisper/Ollama или повторно загружать ранее обработанные встречи.

**Отчёты специалиста удалены как функция по вашему решению.** Их нет ни в динамике, ни у врача, ни у пациента; создать/опубликовать новый отчёт нельзя. Старые записи в SQLite сохранены. Итоги встреч, врачебные решения, результаты опросников и технические результаты импорта — другие действующие функции, они не удалены.

## Проверить тестами

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют временные базы, а не вашу рабочую SQLite. Облачные браузерные проверки выполнены в Linux/Chromium; фактический запуск Windows/PyCharm на вашем компьютере этим не заменяется. Полные результаты — [PROGRESS.md](PROGRESS.md).
