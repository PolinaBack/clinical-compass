# Обновление карточек Авиандра и привязки демо-пациентов

25.10.2026 · U-AVIANDR-LIVE-25, U-DEMO-ROSTER-25.

## Причины

Прежний сервер пересчитывал карточки при открытии страницы, но открытое окно не получало изменения из других окон. Кроме того, краткий вывод показывал только две полные шкалы: повторная PHQ-4 могла не попасть в текст при наличии GAD-7 и PHQ-9. Теперь учитываются все три шкалы и отдельно показано заполнение незавершённых анкет.

Прежний явный сброс демобазы переиспользовал исходные карты A/B для сценариев C/D и сохранял их логины. Поэтому `patient-a`/`patient-b` могли открывать C/D, а отдельных карт A/B не оставалось. Это исправляется отдельной добавляющей операцией с резервной копией. Истории C/D не переименовываются обратно в A/B.

## Обновить в PyCharm

Остановите приложение и worker, выполните в корне проекта:

```powershell
git switch feat/local-mvp
git pull --ff-only origin feat/local-mvp
.\.venv\Scripts\python.exe -m scripts.reassign_demo_patients --db .\data\compass.db
```

**`--reset` не нужен.** Команда исправляет выбранную существующую базу. Если приложение использует другой `COMPASS_DB`, укажите именно его путь в `--db`.

После команды:

| Карты | Специалист |
|---|---|
| A и B | 1 · `specialist` |
| C и D | 2 · `specialist-2` |
| E | Сохраняется прежняя привязка |

Если A/B уже есть, они используются повторно. Если их карты были переиспользованы под C/D, создаются отдельные пустые синтетические A/B. Прежние логины/пароли не сбрасываются. Для C/D создаются недостающие отдельные аккаунты; случайные пароли выводятся командой только при создании, сохраните их в личном менеджере. При наличии другого корректного аккаунта карты сохраняется его логин.

Когда `patient-a`/`patient-b` переводятся с ошибочной карты на A/B, их старые сеансы отзываются: один раз выйдите и войдите заново. Остальные независимые браузеры одного неизменённого аккаунта продолжают работать. Специалисты получают доступ по актуальной привязке карты, прежний врач теряет доступ к переданной карте. Авторство старых анкет/наблюдений сохраняется.

Полная копия БД и имеющийся ключ сохраняются в `data/backups/before-demo-roster-*.db`. Дубликаты A/B, занятые чужой ролью логины и конфликт владельца не объединяются автоматически: транзакция отменяется. Повтор команды не создаёт повторных карт или новых паролей. Обычный CLI `scripts.setup_aviandr_scenarios` теперь также завершает подготовку этим распределением, включая случай явного `--reset`.

Перезапустите приложение и worker:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

В отдельном терминале для текстового объяснения Ollama:

```powershell
.\.venv\Scripts\python.exe -m scripts.patient_ai_worker
```

## Как теперь обновляются карточки

Откройте у ведущего специалиста **Пациенты → карта → Анализ ИИ → Авиандр**. При видимой странице приложение проверяет сохранённые данные каждые пять секунд и сразу при возврате в окно. Если данные изменились, обновляются выводы, основания, вопросы, графики, дата расчёта и предупреждение об устаревшем тексте модели. Открытые подробности и несохранённая форма уточнения врача сохраняются. Во время выделения текста замена откладывается, чтобы не прервать копирование.

В заголовке видно число анкет, количество завершённых форм и последняя **отправленная врачу** версия анамнеза. Пока пациент сохраняет только личный черновик, он не передаётся врачу. После явной отправки новая версия попадает в расчёт. Сохранённые ответы незавершённого опросника показываются как `1/4` и т. п.; окончательная сумма не присваивается до завершения.

Пересчёт карточек выполняется Python без Ollama и не запускает модель/назначения автоматически. Прежнее объяснение Ollama не перезаписывается: если исходные данные изменились, оно скрывается как устаревшее. Для новой текстовой сводки нажмите кнопку объяснения.

Медицинский статус может остаться «недостаточно данных», даже если факты, баллы и вопросы обновились. Полные анкеты сами по себе не создают проверенную инструкцию, диагноз или подтверждение переносимости.

Без JavaScript используйте «Обновить расчёт по карте». При временной потере связи проверка повторяется автоматически; при завершённом сеансе или отзыве доступа автообновление останавливается с сообщением, без перехода на главную и потери текста формы.

## Проверить вручную

1. У специалиста 1 откройте список: есть A/B. У специалиста 2 — C/D; E остаётся у прежнего врача. Попытка открыть чужую карту должна быть запрещена.
2. Оставьте карточки Авиандра открытыми у врача. В другом браузере войдите соответствующим пациентом, сохраните один ответ в новой PHQ-4. Не обновляйте страницу врача вручную: через несколько секунд должна появиться отметка о незавершённой форме и `1/4`.
3. Завершите PHQ-4. На прежней открытой странице врача изменится полная сумма PHQ-4, даже если уже есть GAD-7 и PHQ-9. При этом неподтверждённые медицинские статусы не становятся положительными автоматически.
4. В форме уточнения врача начните вводить текст, не сохраняйте. В другом врачебном окне сохраните возраст или фактор: карточка должна измениться, введённый текст и открытое «Подробнее» — сохраниться. Ссылка на исходный факт продолжает работать.
5. Измените личный черновик анамнеза пациента: у врача он не появляется. Нажмите отправку врачу и проверьте новую версию/вывод после автоматического обновления.
6. При наличии готового объяснения модели измените карту: старый текст должен исчезнуть из актуального блока, четыре Python-вывода остаются.
7. Повторите команду привязок: число карт и существующие пароли остаются прежними. Посмотрите `data/backups`, копия создана.
