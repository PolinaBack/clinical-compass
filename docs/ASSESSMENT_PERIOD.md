# Продолжение ранее начатой анкеты

25.10.2026 · U-QUESTIONNAIRE-PERIOD-25.

## Что исправлено

Сохранение любой формы, кроме HCL-33, требовало `period_ack`, когда конец периода был раньше сегодняшнего дня. Поля подтверждения в интерфейсе не было. Поэтому ошибка 409 мешала не только завершению, но и паузе, переходу вперёд и назад. Это также затрагивало автоматически добавленные PHQ-9/GAD-7 с прежними датами и страницу, открытую до полуночи.

Теперь анкета продолжается в той же сессии без дополнительного подтверждения. Даты периода и прежние ответы не сдвигаются, новые ответы сохраняются обычным способом с историей. Для ранее начатой формы видно короткое пояснение; оно не требует действий. Следует отвечать за указанный у вопроса период. Вопросы безопасности сохраняют свои периоды: месяц, за жизнь, три месяца; HCL-33 — свою инструкцию.

Настоящие конфликты одновременного редактирования, недопустимые значения и нарушения доступа по-прежнему проверяются. Успешное сохранение показывается только после записи на сервере.

## Обновление в PyCharm

Остановите сервер. В терминале корня проекта:

```powershell
git switch feat/local-mvp
git pull --ff-only origin feat/local-mvp
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Сохраните прежнее значение `COMPASS_DB`, если оно задано в конфигурации запуска. В браузере обновите страницу Ctrl+F5 и снова откройте нужную анкету из личного профиля. Если сеанс входа завершился, войдите прежним аккаунтом. Пароли, аккаунты и ответы не сбрасываются, миграций в этом исправлении нет. Пересоздавать БД и запускать `setup_demo` не требуется.

Ответ, который сервер ранее отклонил с 409, не был записан: если он не остался в браузере, выберите его повторно. Уже сохранённые ответы доступны при открытии соответствующего вопроса.

## Ручная проверка на вымышленной карте

1. Откройте вчерашний незавершённый PHQ-4 или PHQ-9/GAD-7 из **Личный профиль → Анкеты**. Должны отображаться исходный период и обычные варианты ответа; отдельного подтверждения периода нет.
2. Выберите ответ, добавьте комментарий и нажмите **Сохранить и сделать паузу**. После обновления страницы выбранный ответ и комментарий должны остаться.
3. Продолжите, ответьте на следующий вопрос, вернитесь кнопкой **Предыдущий вопрос**. Оба ответа должны сохраниться. Заполните остальные вопросы и нажмите **Завершить и отправить**: появятся сохранённые ответы и статус «Отправлено».
4. Если исходные ответы PHQ-4 достигают установленных порогов, заполните автоматически появившиеся PHQ-9/GAD-7. Их исходные даты сохраняются, старый период не мешает прохождению.
5. В отдельном браузере специалиста откройте эту карту и исходные ответы. Должны совпадать значения, комментарии и период; врач не меняет пациентские ответы.
6. Повторите сохранение учебной адаптации C-SSRS: условные переходы остаются; пропущенные по правилу вопросы не превращаются в ответы «Нет».
7. Чтобы проверить смену дня, оставьте страницу вопроса открытой до следующего дня и сохраните ответ. Он должен записаться без требования подтверждения. Не меняйте системные часы ради проверки: автоматический тест уже моделирует этот случай.

## Автоматические проверки

В терминале проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_assessment_period_resume.py
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты создают временные синтетические базы. Первый набор проверяет воспроизведённую ошибку, все пять шкал, паузу/переходы/отправку, смену дня, автоматические уточняющие формы, ветвление безопасности, неизменность дат и работающие проверки конфликтов/ролей/CSRF. Браузерный сценарий `scripts/browser_assessment_period.py` принимает две авторизованные Playwright-страницы и ID временных вчерашних форм; он не предназначен для запуска на рабочих карточках.

Проверка выполнена на Linux и Chromium. Windows/PyCharm проверяются вручную после обновления. Это исправление механизма сохранения, не клиническая валидация шкал.
