# Смысловое сопоставление и цвет всей карточки

27.10.2026 · U-AVIANDR-MATCHING-27.

На странице анализа Авиандра кнопка **«Сопоставить с инструкцией через ИИ»** запускает существующий ИИ-обработчик. Первый запрос к локальной Ollama сопоставляет свободные описания пациента с четырьмя разделами библиотеки: показания, противопоказания, сочетаемость и переносимость. Второй запрос формулирует объяснение с учётом найденных соответствий. Оба прохода используют прежние локальные настройки и модель. Нижняя кнопка объяснения выполняет то же сопоставление, в том числе в режиме свободного ответа.

Модель возвращает по каждому направлению соответствие, несовпадение либо неопределённость, индивидуальную формулировку и цитаты из карты и инструкции/библиотеки. Для показаний дополнительно указывается конкретное зарегистрированное показание. Выдуманные цитаты, отрицательные/неизвестные структурированные факты, неполный ответ и отсутствующие цитаты не становятся положительным совпадением. Это проверка привязки ответа к данным; она не доказывает клиническую точность модели.

Смысловое соответствие свободно сформулированного диагноза зарегистрированному показанию может заменить результат точного поиска «не совпадает» на жёлтый статус до проверки врача. Модель не устанавливает диагноз. Возможное совпадение с противопоказанием, рискованным сочетанием или нежелательным эффектом делает соответствующий блок красным с объяснением и цитатами для проверки врачом. Результат модели не отменяет найденное обычным расчётом противопоказание или риск.

Внутри каждой карточки видны формулировка ИИ и обе цитаты; Markdown отображается тем же безопасным форматированием, что и полное объяснение. Неопределённость и отсутствие данных не объявляются отсутствием противопоказаний. Без модели доступны прежние проверки и подтверждение врача. Если структура сопоставления не получена, свободное объяснение всё равно отображается. Если сопоставление удалось, но отдельное объяснение завершилось ошибкой или оказалось пустым, сохраняется настоящий текст ИИ из первого прохода.

Сопоставление привязано к пациенту и содержимому соответствующего направления, включая версию библиотеки. После изменения этих сведений старые сопоставления не применяются к текущим карточкам. Подтверждение врача дополнительно связано с конкретным результатом сопоставления; новый результат требует сверки. Собственный успешно полученный ответ модели не помечается устаревшим только из-за того, что обновил карточки.

Фон **всей карточки** и соответствующий пункт навигации явно окрашены: жёлтый — требуется уточнение/подтверждение, зелёный — проверенные подходящие сведения, красный — найденное ограничение или несовпадение. Для одиночного результата проверки он выбран в форме заранее; при найденном ИИ показании предложен соответствующий вариант. Врач отмечает проверку и сохраняет, письменное основание необязательно.

Сохранение с JavaScript возвращает актуальный HTML и заменяет карточку и её статус сразу, без перехода на другую страницу и без ожидания пятисекундного опроса. Другие незавершённые формы сохраняются. Запоздалый ответ фонового опроса не может вернуть цвет, предшествовавший сохранению. При ошибке сведения остаются в форме. Без JavaScript действует обычное сохранение с перенаправлением на актуальный расчёт. Подтверждение полноты не скрывает конкретный красный риск; ошибки в исходных данных уточняются существующим механизмом записи врача.

После обновления кода перезапустите веб-приложение **и уже используемый ИИ-обработчик** (`python -m scripts.patient_ai_worker` или используемый альтернативный worker), обновите страницу и запустите новое сопоставление. Новую модель скачивать не требуется. База пациентов, учётные записи, пароли, назначения и 806 исходных строк требований не изменяются.

Проверки и их ограничения: [журнал](reviews/aviandr-matching/checks.md). HTTP-фикстуры модели проверяют протокол, привязку данных и поведение приложения; клиническое качество реальной локальной модели ими не подтверждается.

Уточнение по присланному скриншоту: [подтверждённый анамнез при отсутствующем возрасте](AVIANDR_MISSING_AGE.md). Врач может подтвердить ограничение 18+ прямо в карточке; оставшийся жёлтый статус объясняет конкретный пробел.
