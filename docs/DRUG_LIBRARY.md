# Библиотека препаратов: работа и проверка

Этап LIB разрешён отдельно. E03 отложен по решению пользователя; все 806 требований остаются в плане.

## Открыть в PyCharm и браузере

1. Остановите сервер: красный квадрат Stop в PyCharm или Ctrl+C в Terminal.
2. В Terminal откройте корень `clinical-compass`. Проверьте `git status`. Если у вас есть свои изменения, сохраните их через Commit или Shelve Changes, прежде чем обновляться.
3. Обновите существующую ветку:

   ```powershell
   git fetch origin
   git switch feat/local-mvp
   git pull --ff-only origin feat/local-mvp
   git log -3 --oneline
   ```

   `fetch` получает сведения с GitHub; `switch` выбирает ветку; `pull` обновляет файлы. При конфликте или расхождении истории сохраните текст ошибки. Команды reset и force не нужны.
4. Создайте резервную копию старой базы. Укажите новое имя, чтобы не затереть прежнюю копию:

   ```powershell
   .\.venv\Scripts\python.exe -m scripts.backup data/backups/before-library-2026-10-21.db
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
   ```

   В macOS/Linux вместо `.\.venv\Scripts\python.exe` используйте `.venv/bin/python`.
   Для первой установки выполните начальные шаги README. Не запускайте повторно создание демо-базы поверх своих данных.
5. Откройте `http://127.0.0.1:8000`, обновите страницу Ctrl+F5, войдите прежним логином врача.
   В шапке нажмите **«Лекарства»** или **«Библиотека → Лекарства»**. Адрес раздела — `/medicines`.

Миграция 004 и первое включение исходных справочников выполняются автоматически.
Прежние таблицы, записи, аккаунты и пароли сохраняются. В новой версии есть зависимости openpyxl/defusedxml для чтения XLSX и защиты XML.

## Поиск и карточки

- Введите `Авиандр`, `маритупирдин`, `эсциталопрам` или пример другого бренда, например `Серлифт`.
  Подсказки появляются после двух символов; поиск кнопкой «Найти» работает и без JavaScript.
- Фильтры ограничивают группу и наличие проверенного источника. «Есть проверенный источник» относится к отдельным полям указанного продукта/формы, а не подтверждает всю запись или все бренды МНН.
- Откройте карточку. Подтверждённые врачом фрагменты показываются с точным местом в документе, РУ, формой, редакцией и датой сверки.
- Если сведений нет, это написано прямо. Исходные утверждения Excel доступны в закрытом разделе «для вычитки», со всеми значениями и неизвестными ячейками. Они не объявлены медицинскими фактами.
- Исходный PDF Авиандра и прежняя справка сохранены. Действительность этого листка в ГРЛС пока не подтверждена.

## Импорт Excel

Обе исходные книги сохранены в `docs/inputs/2026-10-21/`. Справочник при первом запуске включает их полностью, со статусом «требуется проверка».

1. Откройте **«Импорт и источники → Библиотеки Excel»**, выберите одну из книг XLSX до 8 МБ.
2. Нажмите **«Предпросмотр Excel»**. Будут показаны ошибки, повторы, новые/изменённые/совпадающие записи и сравнение «До/После».
3. Если есть ошибки, импорт заблокирован; исправьте файл и загрузите снова. Сверяются все обязательные листы и колонки, ID/названия/МНН, связи пар и дубликаты.
4. При корректном файле поставьте отметку о сохранении истории и нажмите **«Подтвердить импорт»**.
5. Отчёт покажет дату завершения. Повтор одинаковой книги не удваивает записи. Если другой импорт изменил справочник после предпросмотра, создайте новый предпросмотр.

Обновление добавляет версию. Исходные файлы, все 14 листов, ошибки, неизвестные значения и прошлые варианты сохраняются в SQLite. Отсутствующие строки не удаляются. Формулы, макросы, внешние Excel-связи и чрезмерные файлы отклоняются. Удаления справочника через интерфейс нет.

## Официальные данные: что возможно сейчас

21.10.2026 проверены HTTPS-запросы к `grls.rosminzdrav.ru`, `grls.minzdrav.gov.ru` и `cr.minzdrav.gov.ru`. Прокси облачной среды вернул `Tunnel connection failed: 403 Forbidden` для всех трёх адресов.
Это ограничение доступа из среды, а не утверждение о неработоспособности сайтов или наличии API. Записи ГРЛС, действующие ОХЛП/ИМП и актуальные клинические рекомендации по Авиандру в этом этапе **не подтверждены**. Автоматическое обновление по вымышленному API не добавлялось.

Врач может самостоятельно получить официальный документ из ГРЛС на своём компьютере и выполнить контролируемый импорт:

1. В блоке официального документа выберите препарат, загрузите PDF инструкции либо XLSX по скачиваемому шаблону.
   Шаблон — ручная структурированная выписка, а не заявленный формат официальной выгрузки ГРЛС.
2. Укажите HTTPS-ссылку на конкретную запись/документ ГРЛС, редакцию, РУ, точный торговый продукт/производителя/форму/дозировку, дату самостоятельной сверки и следующую дату сверки (до 366 дней).
3. Для PDF перенесите только проверяемые фрагменты в нужные поля и укажите страницу/раздел каждого. Незаполненное поле останется неизвестным. PDF не распознаётся автоматически.
   В XLSX лист «Сведения» использует ключи полей из листа «Как заполнить»; лист «Взаимодействия» — коды препаратов, уровень, объяснение и место в документе.
4. Просмотрите содержание, подтвердите импорт. Оно ещё не станет проверенным.
5. Самостоятельно сверьте подлинность и актуальность файла, точный продукт и каждый фрагмент с ГРЛС. В отчёте об импорте сохраните отдельное решение врача с обоснованием и отметкой о сверке.
   Домен ссылки технически проверяется; он сам по себе не доказывает подлинность загруженного файла. Приложение честно обозначает проверку как ручную.
6. При изменении инструкции загрузите новую версию и проверьте её. Более новая проверенная версия того же продукта/РУ/формы заменит прежнюю. Отзыв новой версии и истечение срока не возобновляют старую автоматически.
   Решения о проверке/отзыве, авторы и даты сохраняются. Для разных форм источники показываются раздельно; при нескольких применимых источниках система просит сопоставить их.

В реальной базе сейчас нет официально подтверждённых фрагментов. Синтетические примеры в тестах проверяют программу и никогда не импортируются в рабочую базу.

## Сочетания и сценарии

Откройте **«Проверка сочетаний»**, отметьте два или более препарата и нажмите кнопку проверки.
Для трёх препаратов будут проверены три пары. Дубли выбора не увеличивают число пар; допустимо до 20 разных препаратов.
Подтверждённые записи показывают уровень, объяснение, источник, форму, редакцию и дату ручной сверки.
Неподтверждённые пары из Excel показываются отдельно. Сообщение **«не найдено в нашей базе» не означает «взаимодействий нет»**.
Даже наличие сведений обо всех парах не доказывает безопасность всей схемы.

Раздел «Сценарии с Авиандром» содержит учебные SC-A…SC-E и пример выбора трёх препаратов.
Клинические показания, дозы и преимущества не придуманы; рассмотрение препарата требует действующих российских оснований и врача.
Полные клинические рекомендации, алерты и маршрутизация по SC-A…SC-E остаются открытыми задачами E06/E07.4/E16.

Пациенту этот раздел недоступен. В нём нет действий назначения, отмены и изменения доз.
Будущие назначения должны ссылаться на версию справочника и решение врача, а мониторинг — на назначение и факт приёма. Такой связи библиотека самостоятельно не создаёт.

## Проверить результат

После остановки сервера запустите полный набор тестов:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Проверьте вручную поиск по названию и МНН, три препарата, повторный импорт книги, старый дневник и настройки обеих ролей. Перезапустите приложение: импорт, история и настройки должны сохраниться. Уменьшите окно браузера до ширины телефона. Существующий `scripts.browser_smoke` включает проверку нового раздела на отдельной тестовой базе; данные и пароли тестов не используйте в рабочей базе.
