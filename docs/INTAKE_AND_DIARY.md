# Анамнез, свои вопросы в дневнике и итоги встречи

Обновление от 22.10.2026. Данные сохраняются в SQLite. Прежние аккаунты, дневник, компас, сон, лечение, настройки E01, генограмма, библиотека препаратов и экстренная помощь сохраняются. Это локальный исследовательский проект; новые поля сами не ставят диагноз и не создают назначения.

## Как получить и запустить обновление в PyCharm на Windows

Откройте **Terminal** внизу PyCharm. Если приложение и обработчик уже работают, остановите каждый через **Ctrl+C**. Из корня `clinical-compass` выполните:

```powershell
git status
git switch feat/local-mvp
git pull --ff-only origin feat/local-mvp
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`git status` показывает ваши локальные изменения. Если Git сообщает о конфликте или незакоммиченных изменениях, сохраните свою работу и разберите сообщение; не используйте `reset --hard`, не удаляйте `data` и не запускайте повторное заполнение демоданными поверх базы. `pull --ff-only` получает опубликованную версию без переписывания истории.

Новая основная зависимость `cryptography` нужна для защиты вложений. Для уже настроенных встреч остаётся прежнее окружение из `requirements-meetings.txt`; модели Whisper и Ollama переустанавливать из-за этого обновления не нужно.

До первого запуска сделайте копию существующей базы в новый файл (название должно быть ещё свободным):

```powershell
.\.venv\Scripts\python.exe -m scripts.backup backups\before-intake-2026-10-22.db
```

Если вы задавали другой `COMPASS_DB`, укажите этот же файл через `--source`. Команда по умолчанию копирует `data\compass.db`. Если зашифрованные вложения уже есть, рядом создаётся файл `имя-копии.db.key`; для восстановления нужны **оба** файла. Их нельзя публиковать в GitHub или пересылать в чат.

Запустите приложение:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

При запуске автоматически применяется добавочная миграция `008_intake_and_diary_questions.sql`. Старые строки не переписываются. В браузере откройте **http://127.0.0.1:8000**. Для встреч во втором Terminal запустите:

```powershell
.\.venv\Scripts\python.exe -m scripts.meeting_worker
```

Оба процесса должны быть перезапущены после обновления: формат и версия настроек итогов изменились. Обработчик встреч не нужен для обычной анкеты и текстовых вопросов дневника.

## Пациент: «Профиль → Обо мне»

1. Откройте свой профиль и **«Обо мне»**. Первичная анкета разделена на 15 тематических карточек. Начните с любой; часть дополнительных вопросов свёрнута.
2. Ответьте на несколько вопросов. Над формой появится **«Черновик сохранён»**. Перезагрузите страницу: ответы должны остаться. Без JavaScript используйте **«Сохранить раздел»**.
3. Можно написать своими словами, выбрать «не знаю», «не помню», «обсудить лично», пропустить или отказаться. «Нет» и `0` не означают отсутствие ответа. При смене основного ответа лишние уточнения скрываются; их прежний текст остаётся в личном черновике и не отправляется в неактивной ветке.
4. Для заболеваний, симптомов, препаратов, нежелательных реакций, обследований, визитов и родственников есть **«Добавить…»**. Можно связать собственные карточки друг с другом, прикрепить документ, не помнить точное название. Подсказка названия лекарства не является рекомендацией его принимать.
5. Откройте **«Проверить ответы»**, затем **«Отправить анкету врачу»**. Только после этого ведущий врач получает эту версию. Дальнейшие изменения остаются личным черновиком до новой отправки.
6. **«История отправок»** открывает прежние неизменяемые версии с исходными вопросами и вариантами. При конфликте двух вкладок приложение не перезаписывает свежие данные: обновите страницу, предварительно сохранив отдельно ещё не отправленный текст.

Внизу сохранены **прежние свободные заметки «Обо мне»**. Это старый механизм: его текст, как и раньше, виден ведущему врачу сразу после сохранения. Он явно подписан и отделён от новой приватной анкеты; прежние данные не перенесены и не удалены.

Дата рождения нужна для расчёта возраста на дату консультации. ИМТ показывается только при достаточных данных и допустимом контексте, без оценок «норма/ожирение». При беременности, указанном ограничении весового контроля или настройке врача расчёт скрывается. Менструальные и другие чувствительные сведения добровольны; пол не включает эти вопросы автоматически.

## Врач: просмотр и проверка анамнеза

Откройте **«Пациенты → нужный пациент → Профиль → Обо мне»**. Пока пациент не отправил анкету, его новый черновик врачу не виден.

После отправки доступны краткое резюме из 12 блоков, полная анкета, заболевания, лекарства, визиты, файлы, голос, семья и история. Откройте исходный ответ или карточку и **«Проверить этот факт»**. Можно отметить «подтверждено», «уточнить», «отклонено», «нечитаемо» и оставить примечание. Проверка относится к конкретному факту конкретной отправки; слова пациента и прошлые версии не переписываются. Отметка врача не назначает лечение.

В блоке **«Адаптировать анкету для пациента»** можно скрыть вопросы веса и питания. Семейные карточки могут ссылаться на существующее дерево; сведения родственника не становятся диагнозом пациента. Само дерево не заменяется.

## Врач: добавить собственный вопрос в дневник

Откройте **«Пациенты → пациент → Дневник → Добавить свой вопрос»**. Также ссылка доступна в его анамнезе. Пациент не видит конструктор и не может менять состав вопросов.

Укажите формулировку и формат: шкала, число, да/нет, текст, один или несколько вариантов, время, продолжительность в минутах, дата, файл/фото или голос. При необходимости раскройте параметры и задайте подсказку, единицы, границы/подписи шкалы и период, за который нужно ответить.

В свёрнутых разделах доступны расписание, обязательность, порядок и условие показа. Условие только показывает вопрос, например при низком самочувствии; оно не добавляет клиническое правило тревоги или новое назначение. Предпочтительное время — текстовая подсказка, а не подключённый канал уведомления.

**«Предпросмотр глазами пациента»** открывает пример в отдельной вкладке без сохранения ответа. **«Сохранить вопрос пациенту»** добавляет его в реальный дневник. В списке вопросов можно изменить или приостановить вопрос; изменение создаёт новую версию, а прошлые ответы сохраняют прежнюю формулировку. Устаревшая форма пациента не перезаписывает новую версию.

Проверка: войдите пациентом, откройте дневник, заполните базовые карточки и свой вопрос, сохраните запись; затем откройте дневник врачом. Ответ должен совпадать. Перезапустите сервер и убедитесь, что запись осталась. Для обязательного вопроса допускается отдельная отметка неизвестности/отказа; она не превращается в ноль.

## Документы и собственные голосовые заметки

Для анкеты доступны PDF, PNG/JPEG и аудио до 3 минут. По умолчанию один файл не больше 10 МБ; настройка `COMPASS_ATTACHMENT_MAX_MB` допускает 1–25 МБ. Можно загрузить до 10 файлов, общий размер одной загрузки ограничен тремя лимитами одного файла. Расширение, содержимое, структура и для аудио длительность проверяются сервером. Для звука нужен установленный FFmpeg/ffprobe — тот же, что для встреч.

В самой анкете запись голосовой заметки включается только кнопкой **«Записать»**, после разрешения браузера на микрофон. Для голосового вопроса дневника прикрепите готовую аудиозаметку через поле выбора файла. Её можно прослушать и отменить. Отправка происходит после **«Сохранить выбранные вложения»**. Автоматической расшифровки и отправки внешнему ИИ нет. Врач видит только отправленную заметку, как часть анамнеза или записи дневника. Это отдельные файлы; пациент по-прежнему не загружает и не просматривает записи консультаций.

Антивирус — реальный локальный **ClamAV** с установленным `clamscan` или `clamdscan` и актуальной базой. В облачной проверке антивирус отсутствовал: приложение показывало это честно. Непроверенный файл не получает автоматическое превью; скачать его можно отдельной явной ссылкой. Обнаруженная угроза блокирует доступ. Для проверки установки и повторного сканирования своих файлов:

```powershell
.\.venv\Scripts\python.exe -m scripts.scan_clinical_files --check
.\.venv\Scripts\python.exe -m scripts.scan_clinical_files
```

Скрипт использует выбранный `COMPASS_DB`, не отправляет файлы в сеть, не печатает их содержимое и не расшифровывает речь. Отсутствие ClamAV не заменяется фиктивным «проверено». Установка/обновление самого ClamAV — отдельная настройка компьютера.

Оригиналы новых вложений зашифрованы в БД; ключ впервые создаётся в **`data\attachments.key`** (или `COMPASS_ATTACHMENT_KEY_FILE`, если задан). Если вложения уже есть, а ключ потерян, приложение не заменит его новым: нужен исходный ключ из резервной копии. Старые поля SQLite и прежние записи встреч этим обновлением не переводились на шифрование.

Файл новой анкеты можно удалить до отправки. Отправленный оригинал защищён от случайного удаления через эту форму и остаётся связан с историей. Общие регламенты хранения/отзыва/удаления медданных остаются отдельной незавершённой частью проекта.

## Итоги встречи: 6–7 предложений и следующие шаги

Врач открывает **«Пациент → Консультации и видеосвязь → Записи встреч → встреча»**. У готовой расшифровки снова нажмите **«Подготовить итоги и следующие шаги»**. Перезагружать видео и заново распознавать звук не требуется. Создаётся новая версия итогов.

Ожидаемый формат — 6–7 связных предложений о жалобах/запросе, важных темах и результатах, до четырёх обсуждённых шагов и до трёх возможных дополнений **только врачу**. По короткому или неполному разговору модель не должна дописывать вымышленные факты ради количества. Возможные вопросы к следующему приёму не объявляются доказанной ошибкой врача.

Результат остаётся черновиком: врач сверяет смысл/источники и лекарства, исправляет и отдельно публикует итог и шаги. Приватные дополнения, оригинал и полный текст записи пациенту недоступны. Автоматических назначений или отмен лечения нет. Формат проверен на искусственных данных; скорость и качество вашей локальной модели нужно оценить на компьютере отдельно. Настройка моделей и разбор ошибок — в [MEETING_AI.md](MEETING_AI.md).
