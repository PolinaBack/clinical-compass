После входа пациенту нужен понятный маршрут наблюдения: дневник, изменения состояния и обратная связь специалиста. Прежний экран смешивал его с техническим описанием обследований. Кабинет разделён на «Мой маршрут», «Личный профиль» и «Мой специалист». Экран знакомства содержит три основных вопроса, ссылку на весь FAQ и возможность сначала задать личный вопрос. Материалы перенесены в конец, указанная пользователем подпись FAQ удалена.

Профиль объединяет необязательную биографию, историю состояния, семейную схему, назначенные и пройденные анкеты, отчёты специалиста. Отчёты имеют отдельные поля самоотчёта, наблюдений, заключения и плана; черновик скрыт от пациента до публикации. Специалист комментирует конкретные записи дневника, не меняя их исходный текст.

Анкеты открываются по одному вопросу с серверным сохранением, паузой, комментариями, локальным голосом и отметкой обсуждения. Предыдущие ответы сохраняются при переходе; работают история, null/отказ, защита от повторной отправки и конфликтов вкладок. Библиотека специалиста позволяет назначить PHQ-9, GAD-7, HCL-33 или пакет PHQ-ADS, который атомарно создаёт две формы одной сессии. PHQ-4 предлагает нужное уточнение врачу; назначение остаётся его действием. Положительный п.9 PHQ-9 создаёт независимое событие даже при сохранении отдельного вопроса.

Добавлены два явно вымышленных профиля специалиста с демонстрационной оценкой очереди. Вопросы остаются доступны только назначенному врачу; получение, прочтение и ответ раздельны. Для видеоприёма врач сохраняет время, часовой пояс, HTTPS-ссылку выбранного провайдера и резерв при обрыве; пациент открывает ссылку сам. Завершение приёма требует подтверждения подготовки. Шаблоны начала разговора опираются на исходный ответ, отказ или отметку обсуждения; не отправляются автоматически и не меняют баллы.

Схема БД расширяется добавлением таблиц. Учётные записи, пароли, дневник и анкеты старой версии сохраняются. README содержит Windows/PowerShell/PyCharm и обновление существующего проекта; DB, паролей, токенов и окружения в коммите нет. Матрица требований: docs/UPDATE_V3.md; исходные новые PDF: docs/inputs/Plan.pdf и SpecificationV2.pdf. «Коротко (2)» идентичен уже сохранённому Brief.pdf. По прямому указанию пользователя генограмма сохранена в профиле, хотя один из документов исключает её из MVP.

Проверки: 91 pytest-тест на Linux/Python 3.12, включая права, публикацию отчётов, очередь, видео, шаги опроса и обновление прежней БД; сквозной Chromium-сценарий с отдельными кабинетами, имитатором микрофона, дневником/комментарием, профилем/генограммой, отчётом, PHQ-ADS, вопросом/ответом и ссылкой на видео. Проверены desktop/mobile без горизонтального переполнения и ошибок JavaScript. Windows CI настроен; реальный запуск Windows и реальный видеозвонок отдельно не подтверждены.

После получения текста статьи добавлены шесть учебных вопросов безопасности и условное уточнение, явно маркированные как адаптация C-SSRS. Следующий вопрос выбирается сервером; отказ не запускает отрицательную ветвь; смена ответа сохраняет историю, комментарии и события. Суммы/категории риска нет. Новые «да» создают фактическое событие для специалиста. Затем открывается PHQ-4 с отдельным периодом. Проверены положительная/отрицательная ветви, неизвестный ответ 2, недавность, повторная отправка, голос, доступ и работа перехода без JavaScript.
