# Библиотека врача: разделы и добавление лекарств

С 27.10.2026 [добавление и разрешение назначения разделены](MEDICINE_VERIFICATION.md): сохранённая карточка получает «Не проверен», просмотр/ресурс доступны сразу, назначение открывается после подтверждения регистрации в РФ и проверки инструкции в карточке.

Обновление 26.10.2026, ветка `feat/local-mvp`. Данные пациентов, аккаунты, пароли и прежний каталог сохраняются. Для этой доработки новая миграция или очистка БД не нужны.

## Обновить в PyCharm

Остановите сервер, откройте Terminal в корне проекта и выполните:

```powershell
git switch feat/local-mvp
git pull --ff-only origin feat/local-mvp
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Если у вас уже настроена конфигурация запуска PyCharm, после получения изменений достаточно запустить её снова. Не запускайте команды сброса БД. Приложение использует прежний `data/compass.db` или путь из вашей настройки `COMPASS_DB`.

## Навигация

На главной библиотеке три белые карточки в стиле форумов: «Лекарства», «Рекомендованные ресурсы», «Анкеты». Побочные эффекты открываются через «Лекарства»; отдельной карточки на главной нет. Вверху внутренних страниц есть «← Библиотека».

Внутри лекарств остаются «Побочные эффекты», «Поиск препаратов», «Проверка сочетаний». Страницы «Импорт и источники» и «Сценарии с Авиандром» удалены, их старые адреса отвечают 410. Существующие документы, версии и решения о проверке сохранены; сведения о них доступны непосредственно в карточке препарата. Прежние служебные API работы с документами оставлены для совместимости, без отдельного интерфейса. Анализ Авиандра в карточке пациента не изменён.

## Добавить лекарство вручную

1. Войдите врачом → Библиотека → Лекарства.
2. Перед поиском нажмите «+ Добавить лекарство».
3. Укажите те сведения, которые есть. Название из одного слова принимается; МНН и остальные поля можно оставить пустыми. Если названия нет, карточка будет подписана «Лекарство без названия».
4. При необходимости укажите группу, форму, дозировку формы, производителя, упаковку, РУ, АТХ и другие названия.
5. Раскройте нужные текстовые разделы: показания, применение, состав, противопоказания, особые указания, побочные действия, взаимодействия и т. д.
6. Нажмите «Добавить в библиотеку». Откроется обычная карточка каталога с теми же разделами и действиями, что у исходных препаратов.

Новая запись доступна всем специалистам в общем каталоге и поиске. В выборе лекарства для назначения она видна со статусом «Не проверен» и отключённым добавлением до проверки регистрации/инструкции. Это добавление справочной записи, а не назначение пациенту. Неизвестные сведения обозначаются как невнесённые. Прежние препараты не перезаписываются. Повторная отправка той же формы не создаёт вторую запись; отдельная новая карточка с совпадающим названием разрешена.

Для полей сохраняемой карточки больше нет ограничений 500/15 000 символов: принимается весь длинный и многострочный текст. Полный извлечённый текст также сохраняется в «Ресурсе». [Исправление ошибки длины и обновление](MEDICINE_TEXT_STORAGE.md).

## Добавить по ссылке

1. На той же странице вставьте публичную HTTPS-ссылку на HTML-страницу конкретного препарата.
2. Нажмите «Получить данные по ссылке». Сервер действительно загружает страницу; подготовленный ответ вместо загрузки не используется.
3. Проверьте заполненные поля. Извлекаются структурированные данные Drug/JSON-LD и узнаваемые русскоязычные заголовки разделов. Полнота зависит от сайта. Внизу можно раскрыть извлечённый текст.
4. Исправьте неточности и добавьте недостающее. До нажатия «Добавить в библиотеку» лекарство в каталоге не создаётся.
5. Сохраните. Ссылка видна в отдельном блоке «Ресурс» новой карточки; сведения не становятся проверенной официальной инструкцией автоматически. Неполное извлечение не требует заполнять МНН вручную перед сохранением.

В блоке «Ресурс» автор добавленной карточки может раскрыть «Удалить лекарство из библиотеки» и нажать кнопку удаления. Карточка исчезнет из каталога, поиска, подсказок и выбора новых препаратов. Сведения в прежних назначениях, их версии и сообщения о реакциях сохранятся; удалённая карточка остаётся доступной по прежней ссылке с соответствующей пометкой. Исходные препараты и карточки другого автора этим действием не удаляются.

Поддерживаются публичные HTTPS-страницы на стандартном порту, до 2 МБ HTML, до трёх перенаправлений. Локальные/внутренние сетевые адреса запрещены, в том числе после перенаправления. Чтение не выполняет JavaScript; PDF, авторизация, CAPTCHA, защита сайта и динамическая загрузка могут потребовать ручного заполнения. Если чтение завершилось ошибкой, на той же странице остаётся ручная форма. Неизвлечённые сведения не придумываются.

Добавленный текст о реакциях или взаимодействиях не превращается автоматически в структурированные записи реестра побочных эффектов, подтверждённые взаимодействия или правила анализа ИИ. У новых препаратов сопоставления могут показывать нехватку сведений. Универсальная точность разбора любых сайтов не заявляется.

## Ручная проверка

1. Проверьте три главные карточки библиотеки и одинаковое оформление с форумами. Откройте каждый раздел и вернитесь по ссылке слева сверху.
2. В лекарствах проверьте три вкладки; раскройте систему органов в побочных эффектах. Удалённых вкладок быть не должно.
3. Добавьте вымышленное лекарство вручную, найдите его по названию и МНН, откройте карточку. В назначениях врача найдите эту же запись в выборе лекарства; отправлять назначение для проверки справочника не требуется.
4. Получите данные по доступной странице известного вам препарата. Сверьте поля с содержимым сайта, исправьте одно поле перед сохранением, затем убедитесь, что в карточке сохранена именно правка.
5. Укажите недоступную ссылку или `https://127.0.0.1/`. Должно появиться пояснение, ручная форма должна оставаться доступной, лекарство не должно создаваться.
6. Обновите страницу и перезапустите приложение: созданная карточка должна сохраниться. Убедитесь, что прежние пациенты и препараты на месте.

## Технические проверки и пределы

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_doctor_medicines.py tests/test_drug_library.py tests/test_medicine_workspace.py tests/test_adverse_reactions.py tests/test_interface.py
```

Тесты используют временные синтетические БД. Сетевая загрузка в автоматических проверках подменяется явно обозначенным тестовым HTTP-транспортом; проверяется настоящий код чтения/разбора и последующее сохранение. Это не проверка полноты конкретного внешнего медицинского сайта. Отдельный Chromium-прогон проверяет навигацию, обе формы, редактирование до сохранения, поиск, пять размеров экрана, доступность карточки и отказ локальным адресам. Проверка в нативных Windows/PyCharm и чтение выбранного вами реального сайта остаются ручными.
