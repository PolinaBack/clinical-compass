# Форум врачей

Отдельный закрытый раздел: **Кабинет врача → Форумы → Форум врачей**. Прямая ссылка: `/doctor/forum`. По уточнению U-SPECIALIST-UPGRADE-24 вкладка «Задачи» убрана; оба форума находятся на `/doctor/forums`, сразу после Библиотеки. Прежний публичный FAQ и его модерация сохранены.

## Обновление в PyCharm

Остановите сервер через Ctrl+C и из корня проекта выполните:

```powershell
git switch feat/local-mvp
git pull --ff-only origin feat/local-mvp
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Если используете отдельную тестовую базу, перед запуском сервера укажите её, например `$env:COMPASS_DB="data/ai-test/compass.db"`. При старте добавочная миграция `012_clinician_forum.sql` создаёт три новые таблицы. Удаление базы, повторный setup_demo, модели ИИ и отдельный обработчик для форума не нужны.

Откройте http://127.0.0.1:8000 и войдите врачом. Обсуждения общие для врачебных аккаунтов **одной установки приложения / одной базы**. Разные локальные компьютеры не синхронизируются через Git или Ollama. Для общего форума нескольких компьютеров потребуется отдельно настроенное размещение приложения; текущая работа его не публикует в интернет.

## Публикация и обсуждение

1. Нажмите **«+ Новая тема»**.
2. Выберите **«Клинический случай»** или **«Вопрос коллегам»**, напишите заголовок и описание. Для случая можно указать возрастной диапазон, жалобы, примерный период, уже обсуждавшиеся обстоятельства и вопрос. В форме нет выбора пациента, выгрузки карты или загрузки вложений.
3. Уберите все узнаваемые подробности. Подтвердите проверку обезличивания и нажмите **«Предпросмотр публикации»**. На этом этапе тема ещё не сохраняется в базе и не видна коллегам.
4. Прочитайте результат и нажмите **«Опубликовать тему»**. Тот же процесс применяется к ответам коллег и изменениям текста. Изменённый после предпросмотра текст напрямую опубликовать нельзя.
5. Откройте обсуждение и добавьте ответ. Автор обозначается **«Врач №…»**; имена пациентов и их карточки не подставляются. Список поддерживает раздел, поиск с учётом кириллицы без различия регистра, фильтр **«Мои публикации»**, страницы по 20 тем.

Свои темы/ответы можно изменить или удалить. Удаление темы убирает всё обсуждение вместе с ответами; оно требует явной отметки в раскрытии **«Управление публикацией»**. Текст удаляется из активных строк, остаются технические ID/автор/даты/события. Резервные копии, уже прочитанные страницы или внешние копии автоматически не очищаются.

## Обезличивание и ограничения

Проверка выполняется на сервере при предпросмотре **и повторно при публикации**. Она отклоняет распространённые телефоны/длинные номера, электронную почту, ссылки/контакты мессенджеров, полные календарные даты, типовые ФИО/инициалы/некоторые пары имени и фамилии, явно обозначенные документы/адреса и ссылки на карту. Невидимые форматирующие символы удаляются перед проверкой. Ошибка сообщает тип сведений, без копирования найденного значения в журналы.

Это ограниченная проверка по текстовым правилам, **не полное распознавание имён и не гарантия обезличенности**. Она может пропустить необычную фамилию, написание цифр словами или редкое сочетание профессии/места/события и иногда ошибочно отклонить нейтральный текст. Автор обязан проверить прямые и косвенные признаки: точные адреса, учреждения и места работы, фотографии, редкие события и любые сочетания, позволяющие узнать человека. Безымянное описание тоже может быть узнаваемым.

Если коллега заметил персональные данные, в раскрытии **«Заметили персональные данные?»** можно подтвердить проблему и нажать **«Скрыть из-за персональных данных»**. Тема или отдельный ответ сразу исчезает для других врачей, включая доступ по прямой ссылке. Автор видит свою скрытую публикацию через **«Мои публикации»**, исправляет её и снова проходит проверку/предпросмотр. Это механизм оперативного скрытия участниками, а не отдельная служба экспертной модерации. Настройка привилегированного модератора, независимое рассмотрение жалоб и внешняя проверка квалификации пользователей пока не реализованы.

Файлы, прямые ссылки и автоматическая публикация из карт запрещены. Текст показывается как обычный экранированный текст, без HTML/Markdown-ссылок. Комментарий ограничен 2500 символами, тема — 6000; максимум 200 не удалённых ответов в обсуждении, далее можно создать продолжение.

## Права и хранение

- Пациенту и не вошедшему пользователю недоступны чтение, поиск, создание, ответы, предпросмотр, редактирование, удаление и скрытие. Права проверяются на сервере для каждого действия; отключение аккаунта и отзыв сессии блокируют дальнейший доступ, как в остальных разделах приложения.
- Врач читает опубликованные обсуждения других врачей, включая врачей с другим doctor_id. Это намеренная общая область **без patient_id**, которая не расширяет доступ к чужим картам. Исправлять и удалять можно только свои публикации.
- `clinician_topics`, `clinician_comments`, `clinician_privacy_reports` не связаны с patients/diary/answers/intake. Отсутствуют публикация в публичный FAQ, отправка пациенту, экспорт карты или передача форума ИИ.
- После предпросмотра подписанная сессия хранит только случайный nonce и SHA-256 отпечаток данных/аккаунта. В БД пишется проверенная публикация после явной отправки. Повторная отправка того же nonce не дублирует запись; ревизии защищают от перезаписи конкурентных исправлений.
- Страницы помечены `no-store`/`noindex`, Referer не передаётся. Аудит содержит действие и технические ID без текста обсуждения. Введённые тексты обрабатываются локальным сервером, не внешним ИИ.

## Ручная проверка

Для второго тестового врача можно создать отдельный аккаунт существующей командой. В новом терминале сначала задайте тот же COMPASS_DB, если база нестандартная, затем выполните:

```powershell
.\.venv\Scripts\python.exe -m scripts.create_user --username colleague --role doctor --doctor-id 2
```

Команда попросит придумать и повторить пароль. Войдите этим аккаунтом в отдельном приватном окне браузера, чтобы не выходить из первого врачебного аккаунта. Второму врачу будут доступны обсуждения, но не чужие карты пациентов.

На временной тестовой базе создайте тему и ответ с двух врачебных аккаунтов. Убедитесь, что до публикации коллега ничего не видит, после публикации — видит текст, после обновления страницы он остаётся. Попробуйте свой и чужой режим редактирования, фильтры, повторную отправку и исправление скрытой публикации. Вставьте вымышленную почту `sample@example.org`: ожидается отказ до сохранения. Войдите пациентом и откройте `/doctor/forum`: ожидается 403; без входа — 401. Откройте `/faq`: врачебных кейсов там нет. Проверьте на компьютере и узком экране.

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_clinician_forum.py
.\.venv\Scripts\python.exe -m pytest -q
```

Проверки и изменённые файлы: [результаты](reviews/doctor-forum/README.md), [файлы](reviews/doctor-forum/FILES.md). Тесты используют только временные вымышленные случаи.
