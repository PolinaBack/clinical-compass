# ИИ-анализ любой доступной врачу карты

Уточнение пользователя 24.10.2026 заменяет прежнее ограничение нового анализа одним синтетическим пациентом. Теперь можно анализировать **любую карту, закреплённую за вошедшим врачом**, включая сведения, введённые вручную. Отдельная лаборатория Марии остаётся самостоятельным демонстрационным разделом; она не служит источником или запасным ответом для остальных карт.

## Где открыть

**Кабинет врача → карточка нужного пациента → «ИИ-анализ»**. По уточнению U-SPECIALIST-UPGRADE-24 отдельные кнопки/баннер ИИ на странице списка пациентов убраны, сам анализ сохранён внутри карты. Прямая ссылка: `/patients/ID/ai-analysis`.

Нажмите **«Проанализировать эту карту»**. В очередь попадёт защищённый снимок сохранённых данных именно выбранного пациента. Когда модель закончит, нажмите **«Обновить результат анализа»**. Появятся краткая сводка, гипотезы для проверки и 3–5 вопросов к консультации. Они создаются предобученной локальной моделью через настоящий HTTP-запрос к Ollama.

Тексты результатов не заготовлены. При отсутствии модели или ошибке запроса успешная сводка не показывается. Специального медицинского дообучения этой модели и подтверждённой клинической точности нет. Карта используется как контекст запроса, а не автоматически добавляется в обучающий набор и не меняет веса модели.

## Обновление в PyCharm

1. Остановите сервер и прежний ИИ-обработчик через **Ctrl+C** в их терминалах. Обработчик встреч можно оставить: он независим.
2. Из корня `clinical-compass` выполните:

   ```powershell
   git switch feat/local-mvp
   git pull --ff-only origin feat/local-mvp
   ```

3. Запустите приложение:

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
   ```

   При запуске автоматически применяется добавочная миграция `011_patient_ai.sql`. Прежние записи/история не удаляются. Пересоздание базы и повторное демонстрационное наполнение не нужны. Создавать базу Марии для анализа обычных карт также не нужно.

4. В отдельной вкладке Terminal запустите:

   ```powershell
   .\.venv\Scripts\python.exe -m scripts.patient_ai_worker
   ```

   Обновлённый `scripts.experimental_ai_worker` тоже умеет выполнять анализ карт. Достаточно одного из этих обработчиков; два одинаковых процесса не нужны.

5. Ollama должна работать локально. Проверьте `ollama list`; по умолчанию используется `qwen2.5:3b`. Если она не установлена, загрузите её отдельно: `ollama pull qwen2.5:3b`. Когда сервис не запущен, используйте `ollama serve` или приложение Ollama в трее Windows.
6. Откройте **http://127.0.0.1:8000**, войдите как врач и обновите страницу через **Ctrl+F5**.

Настройки модели совместимы с предыдущим экспериментом. Задавайте их в терминале **перед запуском обработчика**:

```powershell
$env:COMPASS_EXPERIMENT_OLLAMA_URL="http://127.0.0.1:11434"
$env:COMPASS_EXPERIMENT_OLLAMA_MODEL="qwen2.5:3b"
$env:COMPASS_EXPERIMENT_TIMEOUT="900"
```

По умолчанию ожидание 600 секунд, допустимы 60–1800; проверка наличия модели — 10 секунд. Разрешена локальная Ollama без облачных моделей, внешних URL, прокси окружения и HTTP-перенаправлений при анализе. Новых Python-зависимостей не добавлено. Если проект давно не обновляли, установите текущий `requirements.txt`.

При нестандартной рабочей базе задайте одинаковый `COMPASS_DB` серверу и обработчику. `COMPASS_EXPERIMENT_DB` относится только к отдельной лаборатории Марии и не используется для обычных карт.

## Что входит в запрос

- Доступные врачу сохранённые сведения профиля; возраст и пол из отправленной анкеты. ФИО/контакты отдельными полями не передаются. Свободные записи могут содержать имена; это не полная анонимизация.
- Дневник за последние 30 календарных дней до последней непредстоящей записи. При нескольких записях за день числовая динамика использует последнюю. Ноль остаётся нулём, пропуски не заменяются нулём. Показатель тревоги берётся только из реально настроенной шкалы 0–10; отсутствие такой шкалы не выдаётся за отсутствие тревоги.
- Последние восемь сохранённых анкет с фактическими состояниями ответов, суммами и периодами. Для черновика стандартная сумма не объявляется готовой. Значимые исходные ответы о безопасности показываются врачу независимо от результата ИИ.
- Недавние заметки, сообщения, сохранённые комментарии врача, уточнения отправленного анамнеза и дополнительные показатели, доступные ведущему врачу; семейные сведения со слов без автоматического вывода о наследственности.
- Последняя **отправленная врачу** версия первичного анамнеза. После заполнения анкеты пациенту нужно нажать **«Отправить анкету врачу»**. Несохранённая форма и частный неотправленный черновик пациента в анализ не попадают.

Исходные факты F1–F11 можно раскрыть на странице. Есть явные ограничения объёма: до 300 записей при выборе периода, ограниченное число недавних заметок/сведений, общий бюджет контекста. Если часть данных не вошла, отображается предупреждение. Это не анализ всех файлов карты: PDF/аудио/видео автоматически не распознаются. Для записей встреч остаётся отдельная функция.

Каждый запуск сохраняет снимок, модель, режим `patient-card`, версию сборщика, отпечатки данных/запроса и дату. После изменения карты прежний результат помечается неактуальным. Новый запуск берёт новые данные. Если карта меняется между постановкой в очередь и завершением генерации, результат не выдаётся за анализ текущей версии — запуск завершается `card_changed` и предлагается повтор.

## Ручная проверка

1. Откройте любую свою карточку и сохраните отличительную заметку, например вымышленную фразу «Трудно засыпать перед собеседованием». Можно заполнить другие обычные поля; специальная отметка synthetic и зарегистрированный сценарий не требуются.
2. Если заполняете первичный анамнез в кабинете пациента, сохраните ответы и отправьте их врачу. Проверьте, что врач видит эту версию.
3. Врач открывает **«ИИ-анализ»** нужной карты. В раскрытии исходных фактов должны быть эти сведения. Сценария Марии и сведений другой карты там быть не должно.
4. Запустите анализ. Статусы проходят очередь, проверку локальной модели, генерацию и проверку ответа. Процент генерации неизвестен; время последней связи не объявляется процентом готовности.
5. Сверьте полученные вопросы/сводку с введённым текстом. Проверяйте смысл, а не только наличие ссылки на F1–F11. Модель может ошибаться и делать недостаточно обоснованные предположения.
6. Измените заметку и сохраните. Откройте ИИ-анализ: старый снимок отмечен изменившимся. Запустите новый анализ и проверьте новые исходные факты. Предыдущий результат останется в истории.
7. Откройте вторую свою карту: у неё отдельная история, исходные сведения и результаты. В пустой карте кнопка не создаёт вымышленные данные; сначала нужно сохранить сведения.
8. Войдите пациентом и откройте ссылку — ожидается **403**. Врач не получает доступ к чужой карте или анализу через подстановку ID. Отзыв участия, смена ведущего врача или отключение/изменение учётной записи останавливают активную обработку при проверке доступа; результат не сохраняется как успешный.
9. Для проверки ошибки остановите Ollama и создайте новый запуск. Ожидается `provider_unavailable`, без подстановки готовой сводки. История и исходные данные остаются.

Назначения, дозировки, ответы анкет и записи дневника ИИ не изменяет. Результат доступен врачу, автоматически пациенту не публикуется. Предзаданного предпочтения Авиандра нет. Материалы выбираются только из ранее подтверждённых версий каталога; если их нет, источник не выдумывается. [Проверка источников](EXPERIMENTAL_AI.md).

## Сохранение и ограничения проверки

Снимок карты и ответ модели хранятся зашифрованно в `patient_ai_runs` в рабочей SQLite. Используется существующий механизм ключей вложений. `scripts.backup` теперь сохраняет ключ и при наличии только ИИ-снимков. Для восстановления нужны **база и её файл ключа `.db.key`**. При пропаже ключа приложение не генерирует новый поверх старых данных и сообщает об ошибке. Ключи и содержимое карт в Git/журналы не выводятся.

Команды технических проверок:

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_patient_ai.py tests/test_experimental_ai.py
.\.venv\Scripts\python.exe -m pytest -q
```

В окружении разработки проверены реальные сохранения ручного ввода и состав HTTP-запроса, права/разделение пациентов, обновления/история, ошибки, шифрование/восстановление и браузер. Успешный ответ в автоматических тестах является **явно помеченной транспортной фикстурой**, не доказательством настоящей генерации или медицинского качества. Локальная Ollama здесь недоступна; успешную генерацию и качество выбранной модели нужно проверить на вашем компьютере. Работа сервиса на Windows/PyCharm, медицинская валидность, полнота защиты от ошибочных формулировок и клиническая эффективность не заявляются.
