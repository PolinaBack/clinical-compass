# Кабинеты: соответствие новым материалам

Обязательный контекст: Brief.pdf (новый файл «коротко (2)» побайтово совпадает), Plan.pdf (17 страниц), SpecificationV2.pdf (54 страницы), ранее FAQ.pdf, Additional.pdf, исходное задание и листок «Авиандр». Требования документов применяются в пределах запроса пользователя. Последнее сообщение имеет приоритет: семейная схема сохраняется в профиле, хотя спецификация исключает её из первого MVP.

| Требование | Реализация / проверка |
|---|---|
| Цитата, честные ответы, три основных вопроса и полный FAQ рядом | Экран знакомства после входа; FAQ открыт всем |
| Маршрут наблюдения без перечня тестов | Дневник, график самочувствия, комментарии специалиста |
| Личный профиль | Рассказ о себе, течение состояния, здоровье, семейная история; назначенные/пройденные формы и опубликованные отчёты |
| Два специалиста и сроки | Вымышленные демопрофили, оценка очереди, локальный вопрос и отдельные состояния получения/ответа; доступ только у назначенного специалиста |
| Безопасность перед PHQ-4 | Учебная адаптация по дополнительно присланной статье: шесть вопросов и уточнение, отдельные периоды, без суммы/прогноза риска. Официальная self-report форма по-прежнему не подтверждена. Помощь доступна независимо от прохождения |
| Скрытое ветвление C-SSRS | Рабочая учебная адаптация: нужные вопросы выбираются сервером, состояния пропуска и отказа раздельны. Пациенту алгоритм не описывается. Изменение ветви сохраняет историю |
| PHQ-4 обязательно при первичном входе | Короткая анкета отдельно от дневника; полные формы после назначения |
| PHQ-9 / GAD-7 / PHQ-ADS | Предложение врачу по двум подшкалам PHQ-4; пакет PHQ-ADS назначает две формы одной сессии; без новых 16 дублирующих вопросов |
| Один вопрос, пауза, комментарий, голос, обсуждение | Сохранение каждого шага на сервере; пропуск остаётся null; аудио привязано к текущему вопросу |
| Дополнительные формы | Библиотека специалиста с назначением; MADRS/HDRS без точных критериев не активируются |
| Динамика | Самочувствие отдельно от PHQ/GAD; нет автоматического заключения об улучшении |
| Видео | Специалист планирует приём и сохраняет HTTPS-ссылку согласованного сервиса; пациент открывает её сам. Резерв при обрыве обязателен |
| Подбор слов специалисту | Шаблоны уважительного разговора рядом с исходными ответами, без ИИ-диагностики и изменения баллов |
| Библиотека пациента в конце | Горизонтальные материалы после основных функций |
| Разделение кабинетов | Проверки роли и принадлежности на сервере; новые записи не расширяют доступ выбранным демопрофилям |
| Удалить подпись FAQ | Удалён указанный абзац; публичная страница источников не возвращается |

Порядок: 1) новые разделы и аддитивная миграция; 2) отчёты, связь, комментарии и видео; 3) пошаговые анкеты и назначения; 4) тесты прав/расчётов/миграции и браузер; 5) Windows README, архив и GitHub.

Границы: сроки демоспециалистов не являются реальной службой. Консультации требуют выбранного провайдера; запись звонка не ведётся. Для клинического внедрения нужны подтверждения из стр.33 и43 SpecificationV2: формы C-SSRS/MADRS/HDRS, права, медицинский владелец протокола, оператор и работающая служба реагирования. Тексты разработки остаются здесь, пациент получает только понятные действия.

После получения текста статьи добавлена учебная адаптация, а не официальная новая версия C-SSRS. См. CSSRS_ADAPTATION.md: какие формулировки использованы и какие клинические трактовки статьи не перенесены.
