# Клинический компас

Локальный сквозной MVP для кейс-чемпионата: FastAPI + SQLite + Jinja2 + HTML/CSS, небольшой JavaScript без сборки фронтенда. Только синтетические данные.

**Работает:** демороли пациента/врача, привязка к ведущему демоврачу, дневник и график, анкета самоотчёта, история сообщений, сообщения о рисках/нежелательных явлениях, срочные демосигналы с обновлением кабинета врача каждые 10 секунд, подтверждение просмотра, решения врача и категории маршрутизации, семейная схема, необязательный голосовой ввод.

**Клиническая часть не завершена:** нет валидированной шкалы, автоматического клинического триажа и проверенного справочника терапии/«Авиандра». Приложение не ставит диагнозов, не рекомендует препараты и не выполняет клинических действий самостоятельно. [Матрица требований](docs/REQUIREMENTS.md), [обязательные условия и пробелы](docs/CLINICAL_GAPS.md).

## Windows: PowerShell

Установите Python 3.12 (поддерживается Python 3.11+). Откройте PowerShell в папке проекта. Ниже команды не требуют активации окружения или изменения ExecutionPolicy:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# Необязательно: заполнить ПУСТУЮ базу синтетическими примерами
.\.venv\Scripts\python.exe -m scripts.seed_demo
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Откройте в браузере `http://127.0.0.1:8000`. Остановка — Ctrl+C. Если установлен только Python 3.11, замените `py -3.12` на `py -3.11`. При занятом порте используйте `--port 8001`. Не копируйте `.venv` с Linux: создайте её заново на Windows.

Первый запуск создаёт `data/compass.db`. Повторный запуск сохраняет данные. Перезапуск процесса сбрасывает демосессии: выберите роль заново. Смена роли общая для вкладок одного браузера; для одновременного врача и пациента используйте обычное и приватное окно.

## PyCharm на Windows

1. Откройте папку `clinical-compass` как проект (Open).
2. Settings → Project → Python Interpreter → Add Local Interpreter → Existing: выберите `.venv\Scripts\python.exe`. Если окружения нет, сначала выполните команды установки выше в Terminal.
3. Run → Edit Configurations → Add Python. Выберите **Module name**: `uvicorn`.
4. Parameters: `app.main:app --reload --host 127.0.0.1 --port 8000`. Working directory: корень `clinical-compass`. Interpreter: окружение проекта.
5. Run. Professional/FastAPI-плагин, Docker, Node.js и внешняя БД не нужны.
6. Для тестов: в Terminal выполните `.\.venv\Scripts\python.exe -m pytest -q` либо создайте конфигурацию pytest с Target `tests`.

## Демонстрация и данные

[Сценарий демонстрации](docs/DEMO.md). Открытая смена деморолей — не настоящая аутентификация. Запускайте только на loopback; не публикуйте сервис в интернете и не вводите реальные медицинские данные. Сервис не является каналом экстренной помощи. Сохранённое решение «врача» — действие демороли, а не проверка квалификации.

Голосовой ввод работает при поддержке Web Speech API (обычно Chrome/Edge), разрешённом микрофоне и доступе к сервису браузера. Перед запуском требуется согласие: распознавание может отправлять аудио внешнему провайдеру. Ввод не отправляется автоматически; проверьте распознанный текст и сохраните форму. Если функция недоступна, все формы работают с клавиатуры. Реальная запись с микрофона в облачной проверке не тестировалась.

Генограмма — упрощённая направленная семейная схема: сначала добавьте родителя, затем ребёнка с выбранным родителем. Поддерживается один родитель на узел, без циклов, без наследственных расчётов; это не полная клиническая нотация.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют временные базы и не трогают `data/compass.db`. Проверяют полный путь пациент → врач → пациент, роли, CSRF, диапазоны и даты, экранирование, уведомления/подтверждение, семейные связи, резервное копирование и сохранность после перезапуска.

Необязательная браузерная проверка (основной запуск приложения её не требует):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-browser.txt
.\.venv\Scripts\python.exe -m playwright install chromium
# Сначала запустите отдельный экземпляр приложения с ПУСТОЙ тестовой базой
$env:COMPASS_DB = "data/browser-demo.db"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
# В другом терминале, из корня проекта:
.\.venv\Scripts\python.exe -m scripts.browser_smoke --url http://127.0.0.1:8001
```

Браузерный сценарий добавляет синтетические записи. Используйте отдельную базу; не запускайте его на важных данных.

## Резервная копия и восстановление

Из корня проекта, после первого запуска:

```powershell
.\.venv\Scripts\python.exe -m scripts.backup data/backups/demo-01.db
```

Используется SQLite backup API с проверкой целостности, существующий файл не перезаписывается. Для восстановления остановите сервер, сохраните текущую базу отдельно и скопируйте выбранную копию в `data/compass.db`, затем запустите сервер. Будут потеряны записи после момента копии. Автоматическое расписание резервирования и гарантированная экстренная доставка не реализованы. При недоступном сервере события отправить нельзя; успешные POST сохраняются транзакционно.

Переменная `COMPASS_DB` позволяет выбрать другой путь к базе. Секреты для запуска не нужны. Файлы БД, `.env`, окружение и IDE исключены из Git; не добавляйте их через `git add -f`.

## Структура

- `app/main.py` — приложение, SQLite, доступ и серверная валидация.
- `app/templates/`, `app/static/` — страницы и независимые от CDN ресурсы.
- `scripts/` — синтетические данные, backup и необязательная браузерная проверка.
- `tests/` — автоматические тесты; `docs/` — требования, сценарии, ограничения.

Для переноса достаточно исходников/ZIP из GitHub и `requirements.txt`. SQLite входит в стандартную библиотеку Python. На Windows проект необходимо отдельно запустить по инструкции; облачные проверки Linux не доказывают фактический запуск на Windows.
