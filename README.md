# Клинический компас

Локальный исследовательский MVP для кейс-чемпионата: **FastAPI + SQLite + Jinja2 + HTML/CSS + небольшой JavaScript**. Только синтетические данные, возрастной маршрут 18+.

Пациент и специалист входят по отдельным страницам с индивидуальными учётными записями. Права проверяются сервером; выбрать роль кнопкой внутри кабинета нельзя. Для другого аккаунта нужно выйти и войти заново. Специалист видит только закреплённых пациентов.

Кабинет пациента разделён на **«Мой маршрут»** (дневник и комментарии специалиста), **«Личный профиль»** (биография, семейная история, анкеты и отчёты) и **«Мой специалист»** (личные вопросы, переписка и видеовстречи). Экран «С чего начать» содержит краткий FAQ и начало обследования. Материалы находятся в конце страниц.

Работают: открытый FAQ и горизонтальная лента «Полезно каждому пациенту», правила и отзыв участия в демо, PHQ-4, назначения PHQ-9/GAD-7/HCL-33 и пакета PHQ-ADS, черновики/пропуски/история, комментарии и независимые «Новое» / «! Обсудить», дневник, отдельные графики PHQ/GAD, исследовательский PHQ-ADS, события по пункту 9 PHQ-9, подтверждение получения и документирование действия, переписка, семейная схема и локальные голосовые пояснения. Дополнительно работают: пошаговый опрос с серверным сохранением каждого вопроса, отчёт специалиста (личный черновик / публикация пациенту), комментарии к дневнику, вопрос с отдельными статусами прочтения и ответа, назначение видеовстречи со ссылкой и резервным способом связи. Справка «Авиандра» содержит исходный PDF и ссылки на страницы.

**Клиническая готовность не подтверждена.** Формы перенесены из присланных рабочих PDF с указанием источников; первичные версии и права требуют проверки. Есть явно обозначенная учебная адаптация вопросов C-SSRS из предоставленной статьи; это не официальная самостоятельная форма. Врачебные MADRS/HDRS не выдаются за готовые шкалы без точных критериев. Нет автоматической диагностики, назначения препаратов, дежурной службы или гарантированной экстренной доставки. [Новые требования и реализация](docs/UPDATE_V3.md), [материалы для сверки](docs/SCALE_SOURCE_QUEUE.md), [предыдущая матрица](docs/UPDATE_V2.md), [клинические ограничения](docs/CLINICAL_GAPS.md).

## Windows: PowerShell

Установите Python 3.12 (код рассчитан на 3.11+), откройте PowerShell в корне проекта. Активация окружения и изменение ExecutionPolicy не нужны:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# Один раз: создаёт локальные синтетические аккаунты и выводит случайные пароли
.\.venv\Scripts\python.exe -m scripts.setup_demo
# Необязательно, только для пустой базы: примеры дневника/переписки/генограммы
.\.venv\Scripts\python.exe -m scripts.seed_demo
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. Выберите **«Я пациент»** или **«Я специалист»**. Логины: `patient-a`, `patient-b`, `specialist`. Для каждого сгенерирован собственный пароль; сохраните его в личном менеджере. Паролей по умолчанию нет, в исходниках они не хранятся. Повторный `setup_demo` не перезаписывает аккаунты и пароли.

Пациент сначала знакомится с правилами и подтверждает участие в синтетической демонстрации; FAQ и помощь доступны и при отказе. Это не юридическое согласие для работы с реальными медицинскими данными.

Ctrl+C останавливает сервер. При занятом порте используйте `--port 8001`. Если установлен только Python 3.11, замените `py -3.12` на `py -3.11`. Окружение `.venv` с Linux не переносите — создайте его заново на Windows.

SQLite-база создаётся в `data/compass.db`; данные сохраняются после перезапуска. При обновлении кода таблицы добавляются без удаления старых записей. Перед обновлением важной локальной базы сделайте копию. Перезапуск процесса сбрасывает сессии, но не учётные записи: войдите снова. Для параллельной демонстрации пациента и специалиста используйте обычное и приватное окна браузера.

Если пароль потерян, остановите/перезапустите сервер после локальной интерактивной смены:

```powershell
.\.venv\Scripts\python.exe -m scripts.create_user --username specialist --reset
```

Новый пароль вводится скрыто, без аргументов командной строки. Смена пароля отзывает прежние сессии. Дополнительного специалиста можно создать командой `scripts.create_user --username doctor-two --role doctor --doctor-id 2`; привязки пациентов настраиваются владельцем проекта. Веб-регистрации с правом самостоятельно стать специалистом нет.

Professional/FastAPI-плагин, Docker, Node.js и отдельный сервер БД не требуются. Форматирование исходников не является шагом установки.

## Как устроен маршрут

После входа: «С чего начать» — честные ответы, три вопроса и ссылка на полный FAQ, необязательный вопрос специалисту; затем правила участия, учебные вопросы безопасности с автоматическим выбором следующего вопроса и PHQ-4. По подшкалам система предлагает специалисту PHQ-9, GAD-7 или обе формы пакетом PHQ-ADS. Он подтверждает назначение в своей библиотеке. Пациент проходит назначенные анкеты из личного профиля. Дневник и комментарии остаются в «Моём маршруте».

**C-SSRS:** после передачи текста статьи добавлена **учебная адаптация**: шесть вопросов и условное уточнение времени поведения, один вопрос за раз. Система скрывает ненужные вопросы, не приравнивает отказ к «нет», сохраняет историю, комментарии и голос. Новые ответы «да» видны специалисту как фактические события. Суммы, уровней риска и автоматического решения о госпитализации нет. Затем открывается PHQ-4 с отдельным двухнедельным периодом. Возможность отложить беседу не закрывает доступ к помощи и другим учебным функциям.

Это не официальная русская self-report форма: её текст и цифровые права пока не сверены. Ссылки Columbia / Sudact недоступны из среды (403). Для синтетической демонстрации используется присланная статья с явной маркировкой, без её спорных трактовок и автоматического клинического реагирования. [Происхождение и границы адаптации](docs/CSSRS_ADAPTATION.md). Проведённую специалистом беседу по внешней официальной форме можно документировать отдельно.

- PHQ-2 = пункты 3+4, GAD-2 = 1+2 PHQ-4; предложения полных форм по ≥3 на соответствующей подшкале. Назначает специалист; повторную сессию также назначает он.
- Отказ, пауза и отсутствие ответа хранятся как отдельные состояния с `null`, не как 0. Неполная форма не получает стандартную сумму. Завершённая подшкала PHQ-4 может быть показана отдельно.
- Пакет **PHQ-ADS** в библиотеке назначает PHQ-9 и GAD-7 одной сессии одной операцией; повторное нажатие не дублирует формы.
- PHQ-ADS — только полные PHQ-9 и GAD-7 одной сессии, версии и периода. Это исследовательская сумма, не оценка безопасности.
- Сохранённый ответ >0 на пункт 9 PHQ-9 создаёт отдельное событие даже в черновике. Локальный несохранённый ввод не уведомляет специалиста. Есть предупреждение при уходе с несохранённой формы; автоматического хранения ответов в браузере нет.
- Состояния события: создано → получено кабинетом → подтверждено специалистом → действие документировано. Кабинет запрашивает события каждые 10 секунд, пока открыт. Реального клинического резерва нет, и приложение не сообщает об оказанной помощи только по факту отправки.
- «Новое» — непрочитанные дополнения; «! Обсудить» — тема для беседы. Прочтение не закрывает тему. Специалист не изменяет ответы пациента.
- Старый период не меняется молча при возобновлении: нужно подтвердить, что ответы относятся к нему. Срок назначения отображается отдельно. Отправка ответов защищена от повтора одного запроса и конфликтов вкладок.

[Демонстрация](docs/DEMO.md). Не публикуйте локальный сервер в интернете и не вводите реальные медицинские данные. Парольный вход — улучшение демо, а не подтверждение готовности медицинской информационной системы.

## Вопросы, отчёты и видеоприём

Два вымышленных профиля (Анна Миронова и Михаил Лебедев) демонстрируют выбор и занятость. Ориентир ответа: базовые 90 / 240 минут плюс 15 минут на каждый открытый вопрос этого пациента выбранному профилю. Это настройка демонстрации, не SLA медицинской службы. Реально вопрос читает и отвечает **только назначенный этому пациенту специалист**; выбор профиля не расширяет права доступа. Статусы «передан», «прочитан» и «ответ получен» раздельны.

Отчёт создаётся в профиле пациента из кабинета специалиста. Самоотчёт, наблюдения, заключение и план — отдельные поля. Без отметки публикации это черновик, доступный только специалисту. После публикации пациент видит его в профиле и последний план в маршруте. Комментарий к дневнику привязан к исходной записи; врач не переписывает ответ пациента.

В разделе «Связь и видео» специалист указывает дату, время, часовой пояс, HTTPS-ссылку согласованного сервиса и обязательный резерв при обрыве. Пациент видит встречу в «Моём специалисте» и открывает ссылку отдельным действием. Собственного видеосервера и записи звонка нет. Перед завершением приёма специалист подтверждает личность, местонахождение, приватность и резервный способ связи. Для показа можно сохранить `https://example.org/synthetic-video` как явно учебную ссылку — она не является работающей видеокомнатой.

## Голос и семейная схема

Локальная запись пояснения — до 60 секунд в браузере, после отдельного согласия. Можно прослушать до отправки, сохранить исходник и отдельно ввести проверенный текст. Аудио не отправляется внешнему распознавателю; отсутствие расшифровки не блокирует ответы. Хранится в SQLite вместе с данными и попадает в резервную копию. Сервер ограничивает размер 3 МБ, формат контейнера и заявленную длительность; независимое декодирование длительности не реализовано. Нужны поддержка MediaRecorder и разрешение на микрофон. Запись доступна рядом с текущим вопросом; прежде чем отправлять её, сохраните стандартный ответ. Не вводите текст ответа во время записи: переход на другой шаг сбросит неотправленную аудиозапись.

Необязательная **диктовка в дневнике/сообщениях** использует Web Speech API, если браузер его поддерживает. Она может передавать речь провайдеру браузера — перед включением показывается отдельное предупреждение. Этот механизм создаёт текст, а не сохранённое голосовое пояснение. Все формы работают с клавиатуры.

Генограмма — упрощённая семейная схема: сначала родитель, затем ребёнок с выбранным родителем. Один родитель на узел, без циклов и расчёта наследственных рисков. Это не полная клиническая нотация.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют временные базы. Проверяют сквозной сценарий, аутентификацию/права своего врача, CSRF, отзыв участия, нули и пропуски, пороги подшкал, сопоставимость PHQ-ADS, историю и конфликт вкладок, жизненный цикл событий, локальное аудио, семейные связи, пошаговое сохранение, ветви учебных вопросов безопасности и их неполноту, пакет PHQ-ADS, приватность черновика отчёта, комментарии к дневнику, очередь вопросов, подготовку видеоприёма и резервные копии. CI настроен для Windows и Linux; факт успешного запуска Windows CI нужно проверять отдельно.

Браузерная проверка необязательна для запуска приложения:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-browser.txt
.\.venv\Scripts\python.exe -m playwright install chromium
# Отдельная ПУСТАЯ тестовая база, затем сохранить выведенные пароли
$env:COMPASS_DB = "data/browser-demo.db"
.\.venv\Scripts\python.exe -m scripts.setup_demo
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
# В другом терминале из корня проекта; пароли запрашиваются скрыто:
.\.venv\Scripts\python.exe -m scripts.browser_smoke --url http://127.0.0.1:8001
```

Сценарий добавляет синтетические записи и использует звуковой имитатор микрофона, а не настоящий микрофон. Нужна чистая база без `seed_demo`; важные данные для этого не используйте. Скриншоты создаются в игнорируемой папке `artifacts/`.

## Копирование и восстановление

```powershell
.\.venv\Scripts\python.exe -m scripts.backup data/backups/demo-01.db
```

SQLite Backup API копирует согласованное состояние и проверяет целостность. Существующий файл не перезаписывается. Для восстановления остановите сервер, сохраните текущую базу отдельно, скопируйте выбранную копию в `data/compass.db` и запустите сервер. Записи после момента копии будут потеряны; автоматического расписания и резервного сервера нет.

`COMPASS_DB` меняет путь базы. `.venv`, базы, `.env`, артефакты и настройки IDE исключены из Git. Не добавляйте их принудительно.

## Файлы

- `app/main.py`, `app/security.py` — приложение, вход и серверные права.
- `app/portal.py` — профиль, отчёты, комментарии, вопросы и видеовстречи.
- `app/storage.py`, `app/workflows.py` — дополнительные таблицы, анкеты, события, аудио и аудит.
- `app/safety.py` — явно обозначенная учебная адаптация вопросов безопасности без балла риска.
- `app/scales.py`, `app/content.py` — рабочие формы, расчёты и FAQ с происхождением.
- `app/templates/`, `app/static/` — интерфейс без внешних CDN и сборки фронтенда.
- `docs/inputs/` — исходные FAQ, Additional, Brief и новые Plan / SpecificationV2. Файл «коротко (2)» совпадает с Brief. `docs/` — матрицы и ограничения.
- `scripts/`, `tests/` — локальная настройка, копирование и проверки.

Для переноса на Windows достаточно исходников/ZIP, Python и установки `requirements.txt`. Облачные проверки Linux не доказывают фактический запуск на Windows.

## Обновление существующего проекта в PyCharm

Остановите приложение. Сохраните копию локальной базы. В PyCharm выберите Git → Pull для ветки `feat/local-mvp` (после слияния PR — для `main`). При обновлении через ZIP распакуйте исходники поверх проекта, сохранив папки `data`, `.venv`, `.idea` и `.git`. Повторно `scripts.setup_demo` запускать не нужно.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Новые таблицы добавятся при первом запуске. Существующие логины, пароли, дневник и ответы сохраняются. После перезапуска войдите снова и обновите страницу браузера (Ctrl+F5).
